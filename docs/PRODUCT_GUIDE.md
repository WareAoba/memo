# 제품 동작 안내

현재 구현 범위는 [STATUS](STATUS.md), 실행 방법은 [README](../README.md)를 참고한다.

## 화면 구조

공통 UI의 기준과 사용법은 [디자인 시스템 레퍼런스](DESIGN_SYSTEM.md)를 참고하세요. 개발 서버의 [레퍼런스 페이지](http://127.0.0.1:15173/design-reference.html)에서 실제 버튼·입력·박스·드롭다운을 비교할 수 있습니다.

- **당일 요약**: 왼쪽 24시간 원판, 오른쪽 워크 일괄 완료 목록, 하단 워크·태스크 카드. 우상단 아이콘으로 워크를 추가하고 카드 안에서 태스크를 추가·수정합니다.
- **전체 캘린더**: 기본 월 달력과 일간 상세, 연도별 월 선택. 왼쪽 접이식 메뉴 안에서 전환합니다.
- 일간·월간·연간 캘린더 우상단 검색 버튼에서 모든 날짜의 워크·태스크 이름과 스케줄 메모를 검색합니다. 검색 결과에서 스케줄 상세를 열 수 있습니다.
- **프리셋 설정**: 왼쪽 메뉴의 워크 / 태스크 서랍. 워크는 이름·설명·태그 중심으로 입력.

당일 요약과 캘린더 모두 실제 저장된 스케줄입니다. 실행 체크·값·메모는 API/SQLite에 저장되어 새로고침 후에도 유지됩니다.
워크와 태스크 프리셋 CRUD, 워크 기본 태스크 연결·순서는 API/SQLite에 실제 저장됩니다. 스케줄은 당일 요약과 캘린더의 추가 버튼에서 저장합니다. 실행 API는 Phase 7에서 연결했습니다.
화면 골격 검증은 [UX 검증 기록](VERIFICATION_UX.md)을 참고하세요.

당일 요약의 **스케줄 추가** 아이콘이나 캘린더의 날짜별 **스케줄 추가** 아이콘에서 사용합니다. 별도의 저장된 스케줄 관리 페이지는 제거했으며 기존 `#/schedules` 주소는 캘린더로 연결됩니다.

## 현재 기능

- 태스크 이름에 `단어 [n]개 외우기`처럼 입력칸을 정의할 수 있습니다. `[n=5]`는 기본값 5, `[과목]`처럼 한글 이름도 지원합니다. 같은 이름을 여러 번 사용하면 하나의 값을 공유합니다.
- 일정 생성 시 선택한 태스크의 값을 입력하며, 저장한 뒤에도 태스크 수정에서 값과 이름을 변경할 수 있습니다. 문장과 입력값을 일정별로 보존하므로 원본 프리셋이나 다른 일정은 바뀌지 않습니다.
- 데스크톱에서는 워크·태스크 미리보기 오른쪽의 메모 버튼으로 개별 메모를 작성합니다. 버튼에 붙은 팝업이 기본적으로 왼쪽 아래로 펼쳐지며, 화면 여백에 따라 모서리를 전환합니다. 버튼은 hover/키보드 focus 시 표시하고 메모가 있으면 항상 표시합니다. 프리셋 화면은 기본 메모, 일정 화면은 이번 실행의 메모이며 창 안에 저장 범위를 안내합니다.
- 모바일(700px 이하)에서는 메모 버튼과 팝업을 숨깁니다. 모바일·데스크톱 모두 워크·태스크 상세 안에서 메모를 확인하고 수정할 수 있습니다.
- 완료한 태스크에도 메모를 남길 수 있으며, 실패 시 입력을 유지합니다. 작성 중 닫으면 변경을 버릴지 선택할 수 있습니다.

- Rust / Axum JSON API와 실제 SQLite 연결
- 시작 시 SQLx migration 적용, WAL/foreign keys/busy timeout
- GET /api/health: DB 접근 가능 시 `{"status":"ok"}`, 실패 시 503 JSON 오류
- React / TypeScript / Vite 워크 목록·상세·편집 화면과 검색·보관함
- 워크 이름·설명·태그와 선택 정보 저장, 보관과 복원
- 태스크 프리셋 이름·기본 메모·태그와 체크/텍스트/숫자 항목, 순서·필수 여부·기본값·단위
- 태스크 이름/태그 검색, 보관·복원, version과 항목 ID 유지. [Phase 3 검증](VERIFICATION_PHASE3.md)
- 소유자별 API 범위, 입력 검증, transaction, 실패 안내와 재시도
- Caddy를 통한 동일 origin Docker 개발 환경과 영속 데이터 볼륨
- formatter, linter, backend/frontend tests

워크 상세에서 기본 태스크 검색·추가·제거·순서 변경·저장·변경 취소를 제공합니다. 보관된 태스크는 기존 연결에 표시되며 새 연결은 제한합니다.
스케줄 생성·조회·수정과 날짜 필터를 제공합니다. 24시간 원판에서 5분 단위로 시간을 선택하며, 여러 날 스케줄은 시작·종료 날짜와 시간을 직접 입력합니다. 시간대는 앱 설정을 따릅니다. 생성 당시 워크·태스크·항목 정의를 보존합니다. 캘린더 실데이터와 선택적 사진을 지원하며 Google 로그인과 PWA는 후속 단계입니다.
운영 저장 암호화·HTTPS는 배포 요건이며 개발 Compose가 자동 제공하지 않습니다.
민감한 실데이터나 공개 운영 서비스에 이 개발 구성을 사용하지 마세요.


### 오늘 화면의 실행 동작

- 원판의 예정 호는 흰색, 현재 진행 시간은 파스텔 노랑, 종료 후 미완료는 빨강, 완료는 초록입니다. 지나간 스케줄의 부분 완료는 완료 비율만큼 초록을 채우며, 완료 비율이 커지면 초록 명도가 낮아집니다. 건너뜀은 태스크 완료 수에 포함하지 않습니다.
- 워크 목록 클릭은 `POST /api/schedules/{id}/complete`로 모든 태스크를 한 트랜잭션에서 완료합니다. 필수 입력이 남아 있으면 전체 요청이 실패하며 어떤 태스크도 부분 저장하지 않습니다.
- 카드의 태스크 추가는 `POST /api/schedules/{id}/tasks`에 `task_preset_id`를 보내 해당 프리셋의 독립 스냅샷을 추가합니다. 기존 실행 기록을 보존하고 스케줄당 최대 100개를 허용합니다.
- `PATCH /api/schedule-tasks/{id}`의 `name`은 이번 스케줄의 이름만 수정합니다. 프리셋 원본과 다른 스케줄은 바뀌지 않습니다. 실행 메모·세부 값도 카드에서 수정할 수 있습니다.
- 저장 응답을 즉시 반영하며 화면 복귀·연결 복구와 표시 중 30초 간격으로 목록을 갱신합니다. 카드 편집·추가 및 저장 중에는 자동 조회를 멈춰 입력을 보존합니다.


### 스케줄 리마인드

스케줄 추가·수정에서 **리마인드**를 켜고 숫자와 분·시간·일·주를 선택합니다. 기본값은 15분 전이며 최대 365일 전까지 가능합니다. 설정은 SQLite에 저장됩니다.
앱을 보고 있을 때는 우하단 토스트로 표시합니다. 상단 **알림 → 이 기기 알림 켜기**에서 권한을 허용하면 탭을 닫아도 서버 예약 Web Push로 받습니다. 완료·취소·변경된 예약은 발송 전에 다시 확인합니다.
공통 Toast와 리마인드 입력의 실제 데모는 [디자인 레퍼런스](http://localhost:15173/design-reference.html)의 **리마인드와 토스트**에서 확인할 수 있습니다.

서버 예약·기기 구독·VAPID 키 보관·운영 설정과 검증 방법은 [Web Push 안내](WEB_PUSH.md)를 참고하세요.
