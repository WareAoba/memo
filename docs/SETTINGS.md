# 앱 설정과 데이터 초기화

왼쪽 하단 설정 버튼으로 컨텐츠를 전환한다. 왼쪽 탭과 우상단 닫기는 컨텐츠 스크롤과 분리한다. 닫기는 이전 화면·입력 상태를 유지하며, 초기화 성공 때만 삭제된 상세/초안 접근을 막기 위해 이전 화면을 Today로 갱신한다.

설정이 열리면 기존 사이드 메뉴의 상위·하위 항목 선택 표시를 모두 해제한다. 같은 URL의 메뉴를 다시 눌러도 설정을 닫고 해당 화면으로 돌아간다. 상세 항목은 큰 카드로 감싸지 않고 여백과 구분선으로 배치한다. 선택 입력은 공통 `DropdownSelect`를 사용하며, 방향키·Home/End·문자 검색으로 탐색하고 Enter/클릭으로 반영한다. Escape·Tab·외부 클릭으로 닫을 때는 탐색 중인 값을 저장하지 않는다.

## 저장과 로드

`SettingsProvider`가 앱 전체에서 상태를 소유한다. 시작 시 `POST /api/settings/bootstrap`으로 DB 설정을 불러온다. 최초 언어는 브라우저 언어 캐시/감지값, 최초 시간대는 기기 IANA 시간대이며, 이미 저장된 사용자 시간대와 언어는 덮어쓰지 않는다. 기존 `/api/local-user`는 호환 경로로 유지한다.

입력 즉시 UI에 반영하고 변경 필드만 `PATCH /api/settings`로 보낸다. 같은 클라이언트의 요청은 직렬화하며, 처리 중 변경은 다음 요청에 합친다. 서버는 `BEGIN IMMEDIATE`에서 최신 값에 필드를 병합하므로 다른 필드를 동시에 바꿔도 유실되지 않는다. 같은 필드의 충돌은 마지막으로 커밋한 값이 기준이다.

저장 실패 시 선택과 미저장 변경을 유지하고 오류·재시도를 표시한다. 닫아도 저장 큐는 유지한다. 저장 중/미저장 상태에서 브라우저를 떠나면 기본 이탈 확인을 요청한다. 오프라인 영속 큐는 제공하지 않으므로 탭을 강제로 닫으면 미저장 변경은 잃을 수 있다.

포커스 복귀, 온라인 복귀, 문서가 다시 보일 때와 보이는 동안 30초마다 `GET /api/settings`로 새 값을 반영한다. 저장 중/실패 초안이 있으면 원격 값으로 덮어쓰지 않고, 이전 요청의 늦은 응답도 무시한다. 설정 로드 실패 시 입력은 잠그고 재시도한다.

## 필드와 적용 범위

| 탭 | 필드 | 값/기본값 | 반영 |
| --- | --- | --- | --- |
| 일반 | language | ko/en/ja, 최초 브라우저 선택 | UI·날짜 표시·서비스 워커 언어 |
| 일반 | time_zone | 유효한 IANA 시간대, 최초 기기 시간대 | 오늘·캘린더·새 일정. 기존 일정의 시간대 유지 |
| 화면 | theme | light/dark/system, system | 토큰 팔레트·시스템 테마 변경 감지 |
| 화면 | content_scale | 80/90/100/110/125, 100 | 컨텐츠 영역의 배율. 탐색 영역은 고정 |
| 화면 | content_width | compact/standard/full, full | 최대 900px/1200px/전체 너비 |
| 화면 | accent | violet/blue/green/rose/orange, violet | 밝은/어두운 테마별 강조색 토큰 |
| 화면 | motion | system/full/reduced/none, system | 시스템 선호, 전체, 줄이기, 비활성화. 기존 접근성용 OS 감소 규칙도 유지 |
| 일정 | clock_step | 1/5/10/15/30/60분, 5 | 시계판 클릭·드래그·방향키. 기존 시간값을 자동 반올림하지 않음 |
| 알림 | push_enabled | boolean, true | 계정의 모든 기기 푸시 전송 허용. 기기 권한과 구독은 별도 |

시간 입력과 API는 HH:mm 분 정밀도를 허용한다. 이동 단위를 바꿔도 기존 스케줄·워크 기본 시간은 수정하지 않는다. 컨텐츠 배율과 최대 너비는 함께 적용되며 좁은 화면에서는 가용 너비를 따른다.

## 서버 경계

- `GET /api/settings`: 현재 사용자 설정 전체 반환.
- `POST /api/settings/bootstrap`: `{language,time_zone}`로 최초 값을 초기화하고 전체 반환.
- `PATCH /api/settings`: 한 개 이상 변경 필드. null, 알 수 없는 필드, 잘못된 enum/범위/IANA 시간대는 400. 전부 검증한 뒤 한 transaction으로 갱신.
- `POST /api/settings/reset`: `{target,confirmation}`. 두 값이 동일한 schedules/works/tasks여야 한다. 성공 204.

소유자는 클라이언트 ID가 아닌 서버의 `current_user_id()`로 결정한다. 현재 앱의 로컬 단일 사용자 경계를 따르며 향후 세션 인증도 이 경계에 연결한다. `users.settings_json`에 설정을 저장하고 시간대는 기존 `users.time_zone`을 기준으로 함께 갱신한다. GET은 DB 기본값과 시간대를 합쳐 반환한다.

계정 푸시를 끄면 worker의 새 작업 선택과 전송 직전 재조회가 차단된다. 이미 claim된 미전송 작업의 lease를 해제하고 pending으로 보존하여 다시 켰을 때 아직 유효한 알림을 재개한다. 이미 네트워크로 전송한 알림은 회수할 수 없다. 기기별 Push API 권한은 직접 클릭으로 요청하고, 계정 설정을 로드했다고 권한 창을 자동으로 띄우지 않는다. 인앱 리마인드는 이 푸시 전송 설정과 별개다.

## 초기화와 첨부 정리

초기화는 핫세이브 입력이 아닌 명시적인 삭제 동작이다. UI는 삭제 범위를 설명하고 `RESET` 입력 후 영구 삭제 버튼을 활성화한다. 실제 운영 데이터로 검증하지 않는다.

| 대상 | 삭제 | 유지 |
| --- | --- | --- |
| schedules | 모든 일정·태스크 실행·스냅샷·첨부 사진·푸시 전달 기록 | 두 종류 프리셋, 사용자 설정, 기기 구독 |
| works | 보관함 포함 워크·태그 연결·기본 태스크 연결·사용자 정보 종류 이름 | 일정 스냅샷·실행·사진·태스크 프리셋 |
| tasks | 보관함 포함 태스크·항목 정의·태그 연결·워크 연결 | 일정 스냅샷·실행·사진·워크 프리셋 |

사용하지 않는 해당 사용자의 태그만 함께 정리한다. 프리셋 초기화 시 일정의 `entity_id` 또는 `source_task_preset_id`만 NULL로 만들며, 스냅샷과 실행값은 그대로 읽고 수정할 수 있다. NULL이 아닌 연결에는 기존 소유자 복합 FK를 유지한다.

스케줄 초기화는 사진 삭제 대상을 `photo_deletions`에 먼저 기록하고 DB 그래프를 한 transaction으로 삭제한다. 파일 삭제가 실패하면 기록을 남겨 다음 서버 시작의 사진 cleanup에서 재시도한다. 사진 업로드의 마지막 파일 쓰기는 동일 DB 쓰기 transaction 안에서 대상을 재확인하므로 초기화 뒤 늦게 파일을 생성하지 않는다. 설정 migration은 기존 그래프와 인덱스·리비전/리마인드 트리거를 보존한다.
