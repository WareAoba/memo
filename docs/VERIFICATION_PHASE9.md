# Phase 9 검증 — 선택적 사진 첨부

검증일: 2026-09-24

## 완료 범위

- 일반 첨부파일을 제외하고 JPEG/PNG/WebP 사진만 선택적으로 추가한다.
- 일정/태스크 상세의 접힌 사진 영역. 열 때 목록 조회, lazy 이미지, 원본 보기, 추가·삭제 확인.
- 업로드 실패 시 선택 파일 보존, 삭제 실패 시 목록 보존, 조회 실패 재시도.
- 서버 MIME/파일 시그니처·10MiB·대상당 100장 제한·UUID·소유권·복합 FK 검증.
- 보관/취소 일정의 추가·삭제 차단, 조회 허용. 실행/완료 요건에 사진을 추가하지 않는다.
- SQLite photos 메타데이터와 PHOTO_DIR/user_uuid/generated_uuid.extension 저장. 원본 파일명은 경로에 사용하지 않는다.
- pending 기록 후 파일 저장·ready 전환. deleted 표시 후 파일 삭제. 실패나 중단 기록은 서버 시작 전 정리한다.
- no-store/nosniff/CSP 응답과 일관된 오류. 기존 인증 전 로컬 사용자 경계를 유지한다.

## 자동 검증

- 백엔드 39개·프런트 81개 테스트 통과.
- Rust fmt/clippy(-D warnings)/build, Prettier/ESLint/TypeScript/Vite build 통과.
- 사진 API 5개 통합 테스트: 일정·태스크 구분, DB 재연결 영속성, 파일 삭제, 소유권과 DB FK, PDF/SVG/위조 MIME/빈 파일/경로/크기 거부, 보관·취소 잠금, 파일·DB 실패 정리, 중단 pending/deleted 복구, 동시 업로드 100장 제한, 삭제 실패 복구.
- 프런트: 접힘 상태의 조회 지연, 업로드 실패 후 동일 파일 재시도, 서버 성공 후 목록 반영, 삭제 확인과 실패 보존, 잠금 상태 조회, 목록 재시도, PDF·초과 크기 클라이언트 차단.

## 실제 브라우저 및 로컬 반영

- 전용 검증 워크·태스크·일정 생성, 생성한 PNG를 파일 선택창으로 업로드.
- 새로고침 후 사진 유지, img complete/naturalWidth로 실제 디코딩 확인.
- 390×844 사진 UI 확인. scrollWidth 375 <= innerWidth 390, 가로 넘침 없음.
- 사진 없는 태스크를 캘린더에서 완료하고 1/1 상태 반영 확인.
- 검증 사진은 API로 삭제, 검증 일정·워크·태스크는 보관. 기존 일정 2건 유지.
- 서버 중지 후 data/phase8-9-backup-20260924204342에 DB/WAL/SHM 백업, 최신 백엔드 반영.
- 실행 중인 파일 잠금 때문에 CARGO_TARGET_DIR=backend/target-validation에서 검사하고 정상 실행 경로 backend/target/debug에 결과를 복사했다.

## 제한

- 클라이언트 압축·사진 편집·썸네일 재인코딩·HEIC·일반 파일은 제공하지 않는다.
- 현재 MIME/시그니처 검증이며 서버 전체 이미지 디코딩/재인코딩은 하지 않는다.
- 중단된 파일 정리는 재시작 시 수행한다. 단일 서버 인스턴스를 전제로 한다.
- Docker Compose의 사진 볼륨 경로는 반영했지만 이번 검증은 로컬 실행 기준이다.
- 다음 단계는 Phase 10 PWA·오프라인 shell이다.
