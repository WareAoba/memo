# 트랙

제품 계약은 [SPEC](../SPEC.md), 구현 범위는 [STATUS](STATUS.md), 파일은 [CODE_MAP](CODE_MAP.md)를 참고한다.

## 데이터와 계정 경계

SQLite 파일은 공유하되 계정·트랙 단위로 모든 도메인 데이터를 분리한다. 워크·태스크 프리셋, 태그·상세 종류·그룹·숨겨진 이름 카탈로그, 기본 태스크 연결, 일정·독립 스냅샷·실행 항목·메모·사진, 브라우저 스티커까지 포함한다. 자식 데이터는 같은 트랙의 부모를 통해서만 접근한다. 계정 프로필·인증·앱 설정·기기 푸시 구독·저장 용량 한도는 계정 범위다. 사진 정리 대기열은 기존 계정/사진 ID 경로를 유지하는 내부 복구 정보다.

트랙 간 중복 검사, 자동완성 재사용, 프리셋 승격에 따른 숨겨진 실행 정의 갱신은 하지 않는다. 기존 트랙 내부의 중복 규칙은 유지한다. 다른 트랙의 ID로 조회·변경·연결을 시도하면 실패한다. 원본 프리셋과 일정 스냅샷 사이의 기존 독립 계약도 유지한다.

## API

| 요청 | 결과 |
| --- | --- |
| GET `/api/tracks` | `{items:[{id,name}],limit,default_id}` |
| POST `/api/tracks` | `{name}` → 201 `{id,name}` |
| PATCH `/api/tracks/:id` | `{name}` → 200 `{id,name}` |

이름은 공백 제거 후 1–80자, 제어 문자 불가다. 이름을 바꿔도 ID와 데이터 연결은 유지한다. 생성 제한은 `users.track_limit`(기본 3)을 기준으로 `BEGIN IMMEDIATE` 안에서 확인하고 삽입한다. 동시에 요청해도 초과 생성하지 않는다. 초과 요청은 409 `TRACK_LIMIT`, 잘못된 입력은 400, 타 계정 트랙은 404다. 삭제·이동·복사 API는 제공하지 않는다.

도메인 요청은 `X-Track-Id`를 보낸다. 서버 인증에서 정한 계정의 트랙인지 먼저 확인한다. 헤더 생략은 기존 API 호환을 위해 해당 계정의 기본 트랙에 한정한다. 사진 `<img>`의 개별 GET은 헤더를 보낼 수 없으므로 `?track_id=`도 지원하며 소유자를 동일하게 검증한다. 헤더가 있으면 헤더를 우선한다. 생성·수정 본문으로 소속을 바꾸는 것은 허용하지 않는다.

앱 공통 `/api/reminders`, `/api/push/*`, 설정 조회·저장·bootstrap, 기존 시간대 초기화는 트랙 범위를 적용하지 않는다. `/api/settings/reset`은 현재 트랙만 초기화한다.

## 이전과 성능

새 migration만 추가하며 기존 migration은 수정하지 않는다. 각 기존 계정에 `id=user_id`인 기본 트랙을 만들고 전체 도메인 연결을 같은 트랙으로 이전한다. 기존 자원 ID와 사진 파일 경로는 바뀌지 않는다. 복합 FK를 위해 연결 그래프를 새 테이블로 복사한 뒤 자식부터 교체한다. 실제 데이터 대신 임시 DB의 과거 스키마·태그·연결·실행 값·사진 메타데이터로 이전을 검증한다.

계정·트랙·날짜/보관/이름 순서의 복합 인덱스를 사용한다. 트랙 소유 확인은 PK 조회 한 번이며 행마다 확인 쿼리를 추가하지 않는다. 상세의 페이지 일괄 조회는 유지한다. `tracks.revision`은 해당 트랙의 일정·실행·스냅샷 변경에서만 증가하며 사용하지 않는 계정 단위 revision 테이블/트리거는 제거한다. 앱 공통 리마인드 인덱스는 계정 기준으로 유지한다.

도메인 테이블의 `track_id`를 생략한 내부 기존 SQL은 AFTER INSERT 트리거가 해당 소유자의 기본 트랙을 지정한다. 이후 NULL 또는 다른 소속으로 바꾸는 UPDATE는 거부한다. 제품 API의 INSERT는 항상 명시적 트랙을 넣으며 FK는 계정·트랙 관계를 검증한다.

## 브라우저와 알림

선택 트랙은 탭별 메모리 상태이며 계정별 localStorage에 마지막 선택만 기억한다. 다른 탭의 선택 변경을 현재 탭에 전파하지 않는다. 트랙을 바꾸면 작업 화면을 다시 마운트하고 계정 설정과 앱 알림은 유지한다. 진행 중 쓰기는 전환을 막고, 메모 자동 저장을 먼저 마친다. 실패하면 초안과 화면을 보존한다. 화면 편집 이력이 있으면 미저장 입력 폐기 확인을 거친다(저장 완료 후에도 보수적으로 확인할 수 있다).

요청은 시작 시 트랙을 캡처한다. 응답 전에 선택 세대가 달라지면 결과를 버린다. 여러 페이지 조회도 같은 세대를 확인한다. 동시 조회 공유 키는 계정·트랙·선택 세대를 포함한다. 메모 초안 키와 지연 저장도 계정·트랙에 고정한다.

스티커 저장 키는 계정·트랙을 포함한다. 기본 트랙에 저장이 없을 때만 기존 계정 키를 복사해 이전하며 다른 트랙에는 복사하지 않는다. 읽기·쓰기 실패 시 오류를 표시한다. 스티커는 계속 현재 브라우저에만 저장된다.

인앱과 Web Push는 계정의 모든 트랙 알림을 함께 처리한다. `?track=<id>`가 포함된 알림 링크는 해당 트랙으로 전환해 일정을 연다. 이전 링크는 기본/현재 트랙 동작을 유지하며 다른 트랙 데이터를 자동으로 탐색해 노출하지 않는다. 알림 수신 여부와 트랙 선택은 무관하다.
