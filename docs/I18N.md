# 다국어 지원

한국어(`ko`), 영어(`en`), 일본어(`ja`)를 지원합니다. 설정의 일반 탭에서 즉시 전환하며 입력 중인 값과 사용자가 저장한 이름·메모는 유지합니다. 선택은 사용자 DB 설정에 저장되며 `preset.language`는 초기 표시용 브라우저 캐시입니다. 첫 DB 설정 생성 시 캐시 → 지원하는 브라우저 언어 → 한국어 순서로 초기화하고, 이후 접속은 DB 설정을 따릅니다. 저장 실패 시 화면의 선택은 보존하며 설정 화면에서 재시도합니다. API·동기화 계약은 [앱 설정](SETTINGS.md)을 참고하세요. 표시 언어는 스케줄의 시간대와 별개입니다.

## 문구 추가

- `frontend/src/i18n/locales/{ko,en,ja}.json` 세 파일에 같은 의미 키를 추가합니다. 한국어 원문 자체를 키로 사용하지 않습니다.
- 화면 문구는 `tr('영역.의미키')`로 표시하고 컴포넌트에서 `useTranslation()`으로 언어 변경을 구독합니다. 문자열 키는 한국어 카탈로그의 키로 타입 검사됩니다.
- 동적 값은 문장 전체를 번역한 뒤 `{{name}}` 보간으로 전달합니다. React 요소는 문자열 보간에 넣지 않습니다. 복수형은 `_one`, `_other`와 `count`를 사용합니다.
- `aria-label`, `title`, placeholder, 검증 오류, 빈 상태도 번역합니다. API·DB 식별자, 사용자 입력, 태스크 매개변수 이름은 번역하지 않습니다.
- 저장되는 오류 상태는 번역 키를 사용합니다. API에서는 `LocalizedError` 또는 `ApiError`를 던지고, 화면에서 `message()`와 `ErrorBox`를 사용하면 표시 중인 오류도 언어 전환을 따릅니다.
- 날짜 표시는 `locale()`, 월·요일은 `monthLabel()`과 `weekdays()`를 사용합니다. 내부 날짜 키 및 시간 비교용 포맷은 표시 언어로 바꾸지 않습니다.

## 알림과 설치 정보

`npm run dev`와 `npm run build`에서 `scripts/sync-i18n-assets.mjs`가 카탈로그를 기반으로 언어별 웹 앱 manifest와 서비스 워커용 알림 문구를 생성합니다. 생성된 파일을 직접 수정하지 마세요.

언어 선택은 서비스 워커에도 전달되고 IndexedDB에 저장됩니다. 탭을 닫거나 워커가 다시 시작해도 기기 알림의 문구가 선택한 언어를 따릅니다. 서버는 날짜·시각·시간대를 구조화해서 보내며, 사용자가 정한 알림 제목은 그대로 유지합니다. 이 알림 변경을 적용하려면 새 프런트엔드와 백엔드를 함께 실행해야 합니다. 이미 설치된 앱의 이름 반영 시점은 브라우저의 manifest 갱신에 따릅니다.

## 검증

`npm run check:frontend`는 번역 키·치환값의 세 언어 일치, 언어 탐지·저장, 입력 보존, 오류 전환, 날짜·요일, 복수형, 워커 재시작 후 알림 언어를 포함해 테스트합니다. 백엔드 알림 데이터는 `npm run check:backend`에서 검증합니다.
