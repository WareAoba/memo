# 리뷰 후 수정 검증 — 2026-09-24

리뷰 지적 5건과 추가 발견 2건을 수정했다. 현재 검증 범위에서 미해결 결함은 발견하지 못했다. 모든 환경에서 버그가 없음을 보장하는 결과는 아니다.

## 수정과 회귀 검증

1. 사진 파일 정리 실패: 개별 실패는 로그와 재시도 기록을 남기고 다른 파일 정리·서버 기동을 계속한다. 논리 삭제 후 파일 삭제 실패는 204로 응답하고 다음 시작 시 다시 정리한다. 삭제 불가능한 파일 대체 디렉터리, 다른 파일 정리, DB 잔존 기록과 복구, health·일정 API를 검증했다.
2. 일반 편집의 보관 상태 덮어쓰기: 일정·워크·태스크 프리셋의 일반 저장에서 archived를 제외했다. 활성/보관 상태의 요청 payload와 서버 보관 유지 동작을 검증했다. 같은 일반 필드의 동시 편집은 기존 마지막 쓰기 정책을 유지한다.
3. 저장 시간대 초기화: useToday가 해당 렌더의 시간대로 날짜를 계산하도록 변경했다. 기기 날짜와 Pacific/Honolulu 날짜가 다른 실제 App 초기화 회귀 테스트를 추가했다.
4. 캘린더 페이지 누락·중복: 사용자별 revision과 변경 트리거를 추가했다. 후속 페이지의 revision 불일치는 409 SCHEDULE_LIST_CHANGED이며 클라이언트는 부분 결과를 버리고 최대 3회 전체 조회한다. 보관, 개수가 같은 수정, 태스크·항목 실행, 실패 transaction rollback, 다른 사용자 범위, 중복 페이지와 재시도 한계를 검증했다.
5. 가짜 사진 수락: image 디코더로 허용 MIME과 실제 형식·디코딩을 확인한다. 최대 한 변 8192px, 4000만 픽셀, 디코더 할당 256MiB, 동시 디코딩 2건을 적용하고 blocking pool에서 처리한다. 가짜 JPEG·잘린 PNG·초과 해상도 거부와 정상 JPEG/PNG/WebP를 검증했다.
6. 사진 영역 접기 중 업로드 상태 손실: 처음 펼친 뒤에는 패널을 유지해 선택·요청·완료 결과가 사라지지 않게 했다. 지연 응답 중 접기·다시 펼치기와 목록 재요청 방지를 검증했다.
7. 이른 연도의 날짜 오해석: Date의 0–99년 특수 처리와 네 자리 연도 포맷을 보완했다. 0001·0099·0100·윤년·9999를 검증하고 캘린더 이동이 지원 연도 밖으로 나가지 않게 했다.

## 전체 검사

- `npm run check:backend`: rustfmt, clippy(-D warnings), 테스트 42개, debug build 통과.
- `npm run check:frontend`: Prettier, ESLint, 19개 파일의 테스트 97개, TypeScript, Vite production build 통과.
- 실행 중인 바이너리 잠금을 피하기 위해 CARGO_TARGET_DIR=backend/target-validation을 사용했다.
- 자동 테스트는 임시 DB/사진 폴더와 프런트 mock을 사용한다. 기존 사용자 일정의 업무 데이터는 변경하지 않았다.

## 검증 한계

이번 수정에서는 Docker 재빌드, 실제 모바일 기기, 장시간 부하·전원 손실 시험은 수행하지 않았다. 이미지 원본을 재인코딩하지 않으며 애니메이션의 모든 프레임 검증이나 악성 파일 탐지까지 보장하지 않는다. 사진 정리 실패의 자동 재시도는 다음 서버 시작 시 수행한다.

PWA·오프라인 shell, 인증, 운영 배포는 기존 계획의 후속 단계다. 과거 리뷰 및 Phase별 검증 문서는 당시 기록으로 보존한다.
