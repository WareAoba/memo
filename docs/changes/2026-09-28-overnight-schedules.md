# 자정 통과 일정과 시작·종료 입력

## 변경

- 기본 일정은 현지 날짜·시각 기준 0분 초과·24시간 이하로 편집한다. 종료의 자정 통과/복귀에 따라 end_date를 계산하고 시계판과 기간 호를 유지한다. 저장된 날짜·시각 길이가 24시간을 초과하는 경우에만 여러 날 편집으로 다시 연다. 캘린더는 기존 날짜 겹침 막대 배치를 그대로 재사용한다.
- 원판·화살표는 시작/종료 역할을 바꾸지 않고 시간 순서와 24시간 경계에서 멈춘다. 선택 시각 박스에 기존 시·분 휠을 연결하며 유효하지 않은 초안은 적용 불가다. 휠/클릭 종료 시각은 현재 종료와 가까운 날짜에 매핑하여 자정 양방향 변경을 지원한다. 시작 날짜는 선택한 날에 고정한다.
- 여러 날 입력은 공통 DateTimeSection의 시작/종료 fieldset 안에 날짜와 시간을 묶는다. 날짜 역전은 날짜만 교환하며 각 시각은 보존한다. 기본 모드로 전환하면 시각을 보존한 24시간 이하 범위로 돌아간다.
- 서버의 종료 00:00 전용 거부를 제거하고 기존 전체 날짜·시간 순서 검증을 사용한다. 기존 기록도 임의 시각 보정 없이 편집한다. API/DB 이름·마이그레이션·스냅샷·소유자·transaction은 변경하지 않았다.
- 시작 시 존재한 macOS 개발 환경 작업(README, 도구 버전 파일, CODE_MAP, CHANGES, 기존 ledger/기록)을 읽고 보존했다. 이번 작업은 일정 입력과 해당 문서/테스트만 변경한다.

## 문서

- SPEC 시간 UI 계약, STATUS의 시간 원판 범위, DESIGN_SYSTEM의 선택기/섹션 계약, CODE_MAP의 공통 선택기 안내를 갱신했다. API의 end_date 저장 구조는 그대로다.
- 지정 레퍼런스는 `/design-reference.html#date-time-reference`. DateTimePicker/AnchoredPopup/MenuSurface와 ui.tsx를 읽고 기존 시간 휠 열림·키보드 상태를 확인했다. 공통 DateTimeSection을 레퍼런스에 등록한 뒤 제품에서 사용하며 아이콘/모션은 기존 구현을 재사용한다.

## 검증

- 선택 프런트 검사: 4개 파일 44개 테스트 통과. 자정 양방향 이동, 24시간 경계, 교차 차단, 휠 적용 제한, 연도 경계 저장, 기존 자정 일정 재열기, 날짜 자동 교환/섹션, 캘린더 양일 막대를 포함한다.
- 서버 자정 종료 POST/PATCH 및 메모 유지 선택 검사 통과. 날짜별 조회/잘못된 같은 날 자정 종료 거부를 포함한 `npm run check:backend` 전체 검사(rustfmt·clippy·테스트·빌드)도 통과했다.
- 데스크톱 생성 모달에서 시작/종료 섹션 배치와 23:55→00:00 변경 시 다음 날 날짜 표시를 확인했다. 실제 data에 테스트 일정을 저장하지 않았다. 390×844 모바일에서 시간 펼침, 시작/종료 섹션, 휠 열림과 Escape를 확인했다. 임시 뷰포트는 원복하고 생성 모달과 레퍼런스 탭을 유지한다. 실제 터치 기기 관성과 OS 모션 설정 직접 변경은 미검증이다.
- 최초 포맷 명령은 경로 기준 오류, 두 번째는 직접 실행 시 Node PATH 부재로 실패했다. 루트 npm exec와 정확한 frontend 경로로 실행해 변경 파일 포맷을 완료했다.

- 첫 전체 프런트 검사는 5건 실패했다. 이번 계약 변경에 따른 App의 2시간 여러 날 fixture 3건은 26시간 fixture로 갱신하고 Settings의 날짜 오프셋 반환 기대값 1건을 갱신했다. Today의 미수정 테스트 1건은 mock 초기화 시 Promise 부재로 일시 실패했으며 이 원인을 이번 변경 탓이나 기존 확정 실패로 단정하지 않는다. 관련 3개 파일 55개 테스트 재실행은 모두 통과했다. 최종 `npm run check:frontend`는 68개 파일 386개 테스트, 포맷·lint·디자인/구조 검사·TypeScript·빌드 모두 통과했다. 미수정 Today 테스트도 전체 재실행에서 통과했다. 기존 JS 청크 500kB 초과 경고는 남아 있다.

- 최종 diff 검토·`git diff --check` 후 기록을 연결하고 `npm run check:docs`를 통과했다. 변경된 백엔드를 재시작해 `/api/health` 정상 응답을 확인했으며 프런트 서버도 유지한다. 확인 주소는 http://127.0.0.1:15173/#/schedules/new (시작/종료 섹션을 연 생성 초안) 및 http://127.0.0.1:15173/design-reference.html#date-time-reference 이다. 실제 사용자 일정 쓰기나 삭제는 하지 않았다.
