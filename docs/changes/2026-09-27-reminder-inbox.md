# 리마인드 토스트·재알림·알림 목록

## 변경

- 닫기 버튼과 다시 알림 선택 시 공통 Toast가 260ms 아래 이동·페이드 후 제거된다. usePopupExit와 기존 모션 축소 정책을 재사용했다. 정적으로 항상 남아 있던 이전 레퍼런스 Toast는 제거하고 실제 열고 닫는 데모를 유지했다.
- 5/10/30분·1/3시간 뒤 재알림을 계정별 현재 브라우저에 저장하고 폴링/복귀 시 한 번 소비한다. 닫기는 목록을 유지하며 개별/일괄 확인은 재알림도 취소한다. 기존 수신 키를 이어받고 30일·200건으로 기록을 제한한다.
- 상단바 우측에 종 아이콘·미확인 수·목록을 추가했다. NotificationMenu/NotificationDemo를 제품과 지정 레퍼런스에서 공유한다. AnchoredPopup의 기본 폭은 유지하면서 폭 옵션을 추가했고 IconButton의 실제 버튼 ref 전달 타입을 지원한다. 한국어/영어/일본어 문구를 추가했다.
- 시작 이후 재알림 상태 검증을 위해 GET /api/reminders에 최대 200개 UUID include를 추가했다. 소유자·활성 상태·리마인드 설정 조건을 유지하며 SQL은 service에 둔다. migration·실제 DB·키·사진은 수정하지 않았다.
- 시작 시 이미 대규모 미커밋 변경이 있었다. 관련 파일 기존 diff와 최신 기록을 확인하고 임시 사본 대비 이번 변경을 검토했다. 기존 트랙·스티커·일정·공통 UI·탐색 변경을 보존하며 이번 구현으로 주장하지 않는다.

## 문서

- SPEC에 닫기/확인 구분, 재알림 시간·실행 조건, 목록 보관 범위와 브라우저 한계를 명시했다. STATUS, CODE_MAP, DESIGN_SYSTEM, WEB_PUSH, PRODUCT_GUIDE를 갱신하고 CHANGES에 연결했다. I18N의 기존 계약을 따르며 새 언어 정책은 없다.
- 편집 전 지정 토스트/드롭다운 레퍼런스와 Toast, ui.tsx MenuSurface, DropdownSelect, AnchoredPopup, usePopupExit, IconButton, ActionIcon을 확인했다. 완성된 기준은 /design-reference.html#notification-reference다.

## 검증

- 선택 테스트: Reminders/상태 모델/앱 44개 통과. Toast 퇴장·축소/Reminders/상태 모델 추가 검사 19개 통과. Rust reminder_inbox 1개 통과(시작 이후·완료/취소·비활성·계정 격리·UUID/한도).
- 첫 TypeScript 빌드는 toReversed 지원 대상과 nullable 데모 항목/visibility 좁힘 오류로 실패했고 수정 후 빌드 통과했다. 첫 Rust 새 fixture는 소유권 불변 트리거 때문에 실패했으며 테스트 인증 매핑을 바꾸도록 수정 후 통과했다. 기존 실패로 분류하지 않는다.
- 첫 lint의 컴포넌트 외 export 경고 2건은 기존 상태 모듈로 옮겨 수정했다. 최초 한정 포맷 및 기록 작성 명령은 작업 디렉터리 오류로 대상이 없었으며 올바른 경로에서 다시 실행했다.
- 390×844 모바일에서 다섯 재알림 선택지와 3시간 예약 시각·목록·빈 상태·개별/일괄 확인을 시각 확인했다. 실제 사용자 데이터는 저장하지 않고 API 없는 레퍼런스를 사용했다. 실제 터치 기기·OS 설정 수동 변경·실제 3시간 대기·기기 간 알림은 미검증이다. 지연과 회귀는 fake timer로 검증한다.
- 재알림은 인앱 예약이며 앱 종료 중 OS 재발송 기능은 아니다. 저장소 차단은 탭 메모리 fallback이며 종료/숨김에서는 복귀 후 재조회한다. 외부 Web Push 제공자 실전송은 이번 변경 범위에 없다.
- 전체 검사와 최종 화면 검증은 진행 중이며 아래에 실제 결과를 추가한다.

- 전체 `npm run check` 통과: 문서/기록 게이트, Rust fmt·clippy·92개 테스트·빌드, 프런트 포맷·lint·디자인/구조·66개 파일 374개 테스트·TypeScript·빌드. 기존 500kB 초과 번들 경고는 남는다.
- 최종 검토에서 저장 공간 부족으로 쓰기만 실패할 때 읽기 가능한 이전 저장값이 메모리 예약을 덮어쓰지 않도록 보강했다. 해당 회귀를 포함한 Reminders 13개 테스트 통과. 이후 프런트 완료 검사를 다시 실행한다.
- 실제 앱의 상단 우측 버튼과 메뉴를 1280×800 및 390×844에서 확인했다. 모바일 메뉴 x=18, width=360, right=378로 화면 내부다. 레퍼런스에서 토스트 옵션 선택 후 사라짐과 3시간 뒤 예약 시각을 확인했다. 상세 모션의 전체 프레임/실제 터치 기기는 미검증이고 퇴장 완료 후 제거·반복 클릭·축소는 자동 회귀로 검증했다.
- 개발 API는 빌드한 임시 실행 사본으로 재시작해 유지한다. health 200, 새 include 입력 검증 400을 확인했다. 원래 데이터 경로/작업 디렉터리를 유지했으며 실제 데이터를 테스트 fixture로 사용하지 않았다. 앱 http://localhost:15173/#/today 및 레퍼런스 http://localhost:15173/design-reference.html#notification-reference 탭을 유지했다. 뷰포트 해제 API를 호출했으나 레퍼런스는 390×844로 유지되어 모바일 검증 화면으로 남아 있다.

- 최종 `npm run check:frontend` 재실행 통과: 66개 파일 375개 테스트, 포맷·lint·디자인/구조·TypeScript·빌드. 백엔드는 직전 전체 검사 이후 수정하지 않았다. `git diff --check` 통과. 최종 기록 갱신 후 npm run check:docs의 문서/기록 게이트도 통과했다.
