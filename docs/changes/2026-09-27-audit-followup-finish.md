# 2026-09-27 구조 감사 후속 마무리

## 변경

[감사](2026-09-27-code-structure-audit.md)의 후속 1·2차 이후 남은 구조 개선을 진행했다. 시작 시 존재한 UI·다국어·스티커·하네스·일정 상태/조회 변경은 기존 작업이며 이번 성과로 집계하지 않는다. 맡은 기존 파일의 전체 diff를 확인하고 보존했다. 실제 DB·사진·키·migration은 수정하지 않았다.

| 감사 항목 | 조치 |
| --- | --- |
| 1. 태스크 초안 유실 | [1차](2026-09-27-schedule-state-refactor.md)에서 행별 초안·실패 보존·중복 차단 완료. |
| 2. 화면별 완료 차이 | 1차에서 공통 완료 동작·화면 계약 회귀 완료. 이번 서버 필수값 조회 변경은 기존 원자성 계약을 유지한다. |
| 3. 갱신·조회 비용 | [2차](2026-09-27-schedule-query-refactor.md)에서 명시적 알림·조회 공유·캘린더 요약 완료. |
| 4. CSS 소유권 | 상단바/브랜드를 5개 파일에서 shell-calendar.css로 통합. 최종 선언에 가려진 이전 모바일 선언만 제거. 집계 import 순서와 기타 영역 cascade 유지. 12개 화면 조건에서 전후 비교. |
| 5. 상태 모델 | 생성 초안은 1차에서 분리. 이번에 App의 URL 정규화·호환 경로·화면 전이를 workspaceRoute로 분리하고 페이지+단일 overlay로 관리. 직접 URL의 기본 배경, 화면에서 연 팝업의 배경 유지, 설정 복귀·데이터 초기화를 유지한다. |
| 6. 서버 경계·조회·DTO | push 구독 SQL을 기존 push 서비스로 이동. 워크 태그는 페이지 단위 1회, 전체 완료 필수 항목은 일정 단위 1회 조회. ScheduleDetail/ExecutionTask/ExecutionItem으로 응답 조립을 타입화해 긴 JSON 문자열 키 조립을 제거했다. 사용자 정의 snapshot/definition/parameter_values는 기존 JSON 계약 그대로 둔다. |
| 7. 미사용 모듈 | TaskGroupPicker·ScheduleBlock·LanguageSelect 제거. 실제 제품의 그룹 선택·Today 표시·설정 언어 선택은 유지. i18n 테스트는 실제 언어 변경 함수로 입력 보존을 검사한다. health 어댑터는 서버 진단 응답의 계약 테스트용으로 보존하고 구조 검사 예외에 이유를 명시. 공유 번역 키는 소비자가 있으므로 제거하지 않는다. |
| 8. 에이전트 효율 | STATUS를 기능별 현재 상태 표로 압축하고 SPEC의 과거 일정 경로·페이지 일관성 설명을 현재 계약과 구별. 구조 검사와 정상/실패 fixture를 프런트 lint에 연결. 검사에서 발견한 useNames의 HTTP 호출·응답 검증을 api/names로 이동. |

구조 검사는 TypeScript AST의 상대 import/export·문자열 동적 import를 사용한다. 도달 가능성은 타입 참조도 포함하며 순환 검사는 런타임 참조만 포함한다. API→UI·UI fetch/HTTP helper·route sqlx 경계를 확인한다. 동적 경로·별칭/간접 호출·런타임 이벤트·CSS 품질 전체를 증명하지 않는다.

### 적용 범위와 남기는 개선 여지

- 감사는 CSS·DTO를 영역별로 점진 개선하도록 권고했다. 이번에 헤더와 일정 상세 응답 경계를 정리했으며 전체 CSS/모든 서비스 JSON을 재작성한 것은 아니다. 캘린더·day-summary·actions의 기존 cascade 분산은 남는다.
- 비초기 화면 지연 로딩은 감사의 검토 제안이며 이번에 도입하지 않았다. 이 작업에서는 초기 실행 지연·실기기 렌더 시간·큰 데이터셋을 측정하지 않았으므로 성능 향상 수치를 주장하지 않는다. 병행한 [성능 조사](2026-09-27-performance-audit.md)는 별도 작업이며 해당 측정 조건과 시점의 한계를 따른다. 기존 번들 크기 경고는 별도로 보고한다.
- 워크 목록은 기존 2+N 조회에서 비어 있지 않은 페이지 3회(목록·개수·태그), 전체 완료 필수값은 태스크 목록+태스크별 조회에서 일정 항목 1회로 바뀐다. 이는 소스의 SQL 호출 구조 비교이며 벽시계 성능 측정 결과가 아니다.

## 문서

- STATUS·CODE_MAP·CHANGES: 현재 범위, 신규 모듈·구조 검사·회귀 화면과 이번 기록을 반영했다.
- SPEC: 제품 계약을 새로 변경하지 않고 오래된 Phase 5 경로와 Phase 6 페이지 일관성 설명을 정정했다. 기존 독립 스냅샷·소유자·원자성·API 형태를 유지한다.
- DESIGN_SYSTEM·styles README: 헤더 소유권과 독립 회귀 화면을 기록했다. 다른 CSS 파일의 import 순서는 유지한다.
- AGENT_HARNESS: 구조 검사의 범위·예외·한계를 기록했다. 문서/해시 게이트와 훅은 유지한다.
- TASK_CUSTOMIZATION·I18N·WEB_PUSH: 실행·번역·푸시 외부 계약은 바뀌지 않아 추가 수정하지 않았다. 기존 미커밋 문서 변경은 그대로 보존했다.
- 과거 감사와 후속 기록은 당시 검증 이력으로 보존한다. 삭제한 3개 UI의 감사 내 링크만 당시 경로 표기와 후속 링크로 바꿨다. 이 표가 그 후의 조치 상태를 설명한다.
- 최종 기록 명령 대기 중 병행 작업의 성능 조사 보고서·원자료 JSON·CHANGES 링크가 추가됐다. 기록 명령이 미기록 파일을 자동 포함한 것을 확인하고 보고서의 범위·방법·미검증 설명과 JSON 구조를 읽었다. 기존 문서 추가를 보존·연결한 것이며 측정 자체를 이 작업에서 수행하거나 독립 재검증한 것으로 주장하지 않는다. 해당 보고서의 기록 연결 보류 문장은 당시 상태이고, 이번 최종 문서 검사에는 함께 포함된다.

## 검증

- 선택 프런트: App·workspaceRoute·i18n 3개 파일 44개 테스트 통과. 이후 데이터 초기화 상태 보존 회귀를 보강했으며 전체 검사에서 다시 확인한다.
- 선택 백엔드: entities/execution/push/schedules 51개 테스트 통과. 이후 빈 태그·공유 태그·페이지 경계를 비교하는 회귀를 추가했으며 전체 검사에서 확인한다.
- 구조 검사 자체의 3개 정상/위반 fixture와 현재 111개 모듈 검사 통과.
- 브라우저: 독립 header fixture에서 390/1280px × light/dark × full/reduced/none 12개 조합의 헤더·브랜드·추가 버튼 위치/크기와 15개 계산 스타일 속성이 변경 전후 동일했다. 모바일 밝은 테마·데스크톱 어두운 테마 스크린샷도 확인했다. 실제 계정 설정/데이터를 변경하지 않았다. 비교용 이전 CSS 임시 파일은 제거하고 재사용 가능한 현재 fixture만 남겼다.
- 중간 실패: 샌드박스의 esbuild/Node/Git 자식 프로세스 EPERM은 권한 확장 재실행으로 해결. 제거한 LanguageSelect import가 줄바꿈 차이로 남아 첫 프런트 재검사에서 실패했으며 수정 후 통과했다. 최초 시각 비교는 테마 적용 전 시점을 읽어 차이가 발생해 동기 테마 설정·load 완료 후 변경 전 CSS와 다시 비교했다. 모두 이번 작업 중 확인한 실패이며 기존 코드의 실패로 분류하지 않는다.
- 백엔드 완료 검사: review 빌드 경로에서 문서 게이트·fmt·Clippy(`-D warnings`)·전체 cargo test·build 통과.
- 프런트 완료 검사 첫 실행은 Node 전용 구조 검사 fixture를 Vitest도 수집해 `No test suite found`로 실패했다. 제품 테스트 55개 파일 303개는 통과했으나 전체 검사는 실패로 기록한다. Node 전용 파일을 check-structure-tests.mjs로 이름을 바꿔 실행기 충돌을 제거했고 Node 검사 명령·문서 경로도 함께 갱신했다. 제품 테스트의 검색 범위는 줄이지 않았다.
- 최종 `npm run check:frontend`: 문서 게이트·Prettier·ESLint/design·구조 검사 3개 fixture/111개 모듈·55개 파일 303개 제품 테스트·TypeScript·Vite build 통과. JS 570.42 kB / gzip 173.77 kB이며 기존 500 kB 경고는 남는다.
- 최종 diff와 추가 파일을 검토했고 `git diff --check` 통과(기존 CRLF 정규화 경고). 프런트 완료 검사의 문서 게이트는 Markdown 49개 로컬 링크·변경 142개 파일 기록을 통과했다. 이 결과 문장 갱신 후 기록 명령과 `check:docs`를 다시 실행한다. 중간에 사라진 Node fixture 이름도 삭제 상태로 기록되어 있다.
- 문서 게이트는 삭제 파일 링크 정정으로 바뀐 과거 감사 본문의 해시를 거부했다. 과거 판단/검증은 보존하고 문서 유지보수 이유를 원래 기록에도 명시한 뒤 원래 기록과 이번 기록을 순서대로 재연결했다. 게이트를 끄거나 기존 실패를 성공으로 바꾸지 않았다.
- 미검증: 실제 기기/큰 데이터셋의 렌더·성능 측정, 원격 CI, 실운영 DB·사진·푸시 전달. 헤더 시각 검사를 앱 전체 시각 회귀로 해석하지 않는다.
