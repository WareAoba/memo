# 일정 입력 밀도·시간 드롭다운·7일 리마인드·더미 프리셋

## 변경

- 검색 중 문구를 Picker, WorkTasks, TaskDirectory에서 제거했다. 검색 실패/재시도와 결과 표시는 유지한다.
- 시간 휠을 전체 모달에서 캘린더와 같은 비모달 드롭다운으로 변경했다. 공통 MenuSurface/usePopupState 진입·퇴장, 화면 경계 보정, Escape/바깥 클릭/포커스 이탈/적용 후 포커스 복귀를 사용한다. 모달 안의 날짜·시간 팝업은 상위 dialog에 연결해 inert로 조작이 막히지 않게 한다.
- 시계 위 화살표의 52px 높이를 미리 예약하고 그 안에서만 움직이게 했다. 편집 모달의 260px 시계 제한을 최대 420px로 확대했다. 태스크 목록은 기존 presets 아이콘으로 태스크 바로 위에 배치하고 생성/저장된 일정의 행 여백을 줄였다.
- 리마인드는 분/시간/일 메뉴와 최대 10080분/168시간/7일을 사용한다. 서버도 초과 및 주 단위 입력을 거부한다. 새 migration은 기존 주/초과 간격을 7일로 보정하고 알림 시각을 재계산한다. 기존 버전 트리거와 전달 취소 정책을 유지한다. 적용된 과거 migration은 바꾸지 않았다.
- AGENTS와 AGENT_HARNESS에 서버·미리보기 프로세스 및 검증 화면을 완료 후 유지하도록 명시했다.
- 사용자 요청에 따라 로컬 My Track에 `테스트 ·` 이름/`demo-20260927` 태그의 워크 30개와 8개 그룹 태스크 120개, 워크별 4개씩 기본 연결 120개를 추가했다. 매개변수 기본값/필수 입력 및 선택 체크 항목도 포함한다. 기존 항목은 수정하지 않았다. 대괄호 접두어는 태스크 매개변수 문법과 충돌하므로 일반 텍스트 접두어를 사용했다.
- scripts/seed-demo-presets.mjs는 명시적 트랙·로컬 서버만 허용하며 기존 이름/태그를 확인해 재실행 시 중복을 만들지 않는다. 실행: `node scripts/seed-demo-presets.mjs --track <트랙 UUID>`. `--dry-run`은 API 쓰기 없이 fixture만 출력한다. 실제 DB를 자동 테스트 fixture로 사용하지 않았다.
- 기존 트랙·스티커·서버·문서 변경이 있는 작업 트리를 유지했다. 이번 기록은 이전 입력 개선 이후 위 후속 요청만 설명하며 기존 작업을 되돌리지 않았다.

## 문서

- SPEC/PRODUCT_GUIDE/WEB_PUSH의 리마인드 제한, 시간 팝업과 태스크 목록 계약을 갱신했다. TASK_CUSTOMIZATION, STATUS, CODE_MAP에 새 UI와 경로를 반영했다.
- DESIGN_SYSTEM의 date-time-reference, task-directory-reference를 갱신했다. CalendarDatePicker, MenuSurface, usePopupState/usePopupExit, IconButton/ActionIcon.presets, 기존 토큰을 참조했다. 새 AnchoredPopup을 공통 폴더에 두고 DateTimePicker를 통해 레퍼런스/제품에서 공유한다.
- AGENTS/AGENT_HARNESS에 확인 환경 유지 지침을 기록했다. 실제 프리셋 데이터는 Git 기록 대상이 아니므로 실행 결과를 이 문서에 남긴다.

## 검증

- 프런트 테스트 중간 실행: 64개 파일/357개 통과. 7일 경계와 주 메뉴 제거, 비모달 시간 팝업 Escape/바깥 클릭 회귀 추가.
- Rust 일정 테스트: 18개 통과. 세 단위의 정확한 7일/초과/주 입력 거부, 이전 주/초과 간격 migration과 ID 보존·버전 증가·재실행 무변경 검사 포함.
- 더미 생성기 테스트 2개 통과. 실제 API 최초 실행 30/120/120개 생성, 재실행은 모두 0개 생성/연결로 확인했다.
- 중간 실패: TypeScript를 루트에서 잘못 실행해 실패했으며 frontend에서 재실행했다. 신규 Testing Library 테스트의 잘못된 exact 옵션은 제거 후 TypeScript 통과. Rust 검사 중 실행 중 exe 잠금으로 실패해 해당 서버를 재시작한 뒤 통과했다. 개발 서버는 빌드 exe 임시 사본으로 다시 가동해 이후 빌드와 확인을 함께 유지한다.
- 브라우저 실측: 편집 시계 420px, 생성 태스크 4개 행 각각 50.4px. 화살표 열기 전후 시계 y=299px 동일, 화살표 하단 287.8px로 원판과 겹치지 않는다. 실제 모달 내부 팝업을 조작해 01:59 시·분 선택과 키보드 접근을 확인했다.
- 브라우저 검사 중 body portal의 중첩 모달 포커스 차단을 발견해 날짜·시간 모두 상위 dialog portal로 수정하고 실제 조작을 재검증했다.
- 최종 `npm run check` 통과: Rust fmt/clippy/101개 테스트/build, 프런트 포맷/lint/디자인/구조 검사/64개 파일 359개 테스트/TypeScript/build. 신규 팝업 ref prop 이름의 ESLint 오류는 `popupRef`로 의도를 명시해 수정했으며 규칙을 우회하지 않았다. 더미 생성기 2개 테스트도 재통과했다.
- 390×844 모바일에서 시간 팝업은 x=30.8/y=450.8, 280×373.6px로 화면 안에 표시되고 문서 가로 폭도 390px를 유지했다. Escape는 바깥 일정 모달을 닫지 않는다. 공통 진입 호출·퇴장 완료 후 적용/제거는 애니메이션 mock 회귀로 검증했다. 실제 터치 기기의 관성 스크롤과 OS 푸시 전달은 이번에 검증하지 않았다.
- Vite의 500kB 초과 청크 경고는 남아 있으나 빌드는 성공했다. 백엔드 생존 확인 시 `/health`는 잘못된 경로로 404였고 올바른 `/api/health`에서 정상 응답을 확인했다.
- 앱 `http://127.0.0.1:15173/`과 백엔드 3000 포트를 유지했다. 더미 태스크 목록과 날짜/시간 디자인 레퍼런스 브라우저 탭을 유지 대상으로 지정하고 닫지 않았다.
