# 시계판 투명 경계와 둥근 끝 충돌 분리

## 변경

- 기존 미커밋 환경·일정 시간·Today 상태/반응형·태스크 작업을 보존했다. 이번 수정은 직전 둥근 호의 투명 외곽과 끝부분 겹침 판정에 한정한다.
- TodayDialStroke에서 호/시작만 막대의 실제 도형과 마스크 도형을 공유한다. TodayDialSeparation은 각 도형 바깥 0.8 SVG 단위의 얇은 경계 합집합을 일정 레이어에서 제거한다. 호와 막대가 교차해도 경계 부분은 투명하며 원래 시간대 배경이 보인다. 시계 눈금·현재 시각 바늘은 마스크 밖이다. 자정 본체/연속 구간은 하나의 외곽으로 처리하며 일정별 외곽을 합집합으로 빼므로 입력 순서에 영향을 받지 않는다. 마스크는 일정 배치가 바뀔 때만 다시 렌더한다.
- 열 배치에 기본 최대 폭 28px의 둥근 cap과 경계 여유를 시간 각도로 환산해 포함한다. 맞닿거나 짧은 간격의 호도 분리하고 ±하루로 이동한 범위를 비교해 24시/00시 경계도 검사한다. 최대 폭 기준으로 보수적으로 공간을 확보하므로 좁아진 호라도 고정 열을 유지한다. 충분히 떨어진 일정은 전체 두께, 시작만 막대는 기존 방사형 도형과 투명 경계를 사용한다.
- 저장 시간·상태·API·DB는 변경하지 않았다.

## 문서

- SPEC·DESIGN_SYSTEM에 투명 경계와 cap 포함 배치 계약을 반영했다. STATUS·CODE_MAP에는 현재 구현과 새 도형/마스크 파일을 안내하고 CHANGES에 연결했다.
- 편집 전 DESIGN_SYSTEM·관련 SPEC·직전 변경 기록 및 실제 TodayDial/배치 구현을 읽고 /design-reference.html#today-dial-reference를 확인했다. 같은 실제 컴포넌트를 사용한 레퍼런스에 교차 막대, 종료/시작이 같은 호, 5분 간격 호를 추가했다.

## 검증

- 선택 테스트 3개 파일 33개 통과: 인접/5분 간격/자정 양쪽의 열 분리, 입력 순서 안정성, 충분한 간격의 전체 폭, 고정 열·자정 연속 유지, 호·막대 공통 투명 마스크와 경계 폭, 기존 완료 반영.
- 브라우저 라이트·다크 레퍼런스에서 교차 막대 주변의 투명 틈, 05:00에 맞닿은 두 호 및 06:00→06:05의 분리, 자정 이후 흐림을 확인했다. 실제 반지름은 인접 일정에서 131/145로 분리되고 두께는 각각 12로 일정하게 유지된다. 실제 데이터 쓰기는 실행하지 않았다. 별도 물리 모바일/다른 브라우저 렌더러는 미검증이다.
- 최종 `npm run check:frontend` 통과: 문서/변경 게이트·포맷·ESLint·디자인/구조 검사·70개 파일 415개 테스트·TypeScript·Vite 빌드. 기존 500kB 초과 청크 경고는 유지된다. 백엔드는 변경하지 않아 재검사하지 않았다.
- 최종 diff와 공백 오류를 검토하고 `record:change` 및 `check:docs`를 갱신했다. 실제 당일 화면의 같은 색 호/막대 교차 틈도 확인했다. 개발 서버와 http://127.0.0.1:15173/#/today 및 http://127.0.0.1:15173/design-reference.html#today-dial-reference 탭을 유지한다.
