# 스티커 공간·일정 직접 입력·태스크 목록 개선

## 변경

- 사용자 요청 1~12를 반영했다. 13번은 내용이 없어 추가 요구로 해석하지 않았다.
- 스티커 상단바를 본문과 겹치는 28px 오버레이로 바꾸고 하단 여백을 줄였다. 터치 조작 영역은 44px를 유지한다. 앱 우상단 진입 버튼과 대상 선택 모달을 제거하고 보관함의 스티커 추가는 자유 메모를 즉시 만든다. 기존 일자/일정 스티커 데이터와 일정에서의 고정 동작은 유지한다.
- 워크 이름은 입력 즉시 생성 초안으로 반영하고 검색 결과는 선택적 힌트로 제공한다. 공통 Picker의 이름 사용 버튼을 없애 태스크 직접 입력도 Enter/blur로 확정한다.
- 태스크 추가 후 그룹→개별 태스크 목록 팝업에서 다중 선택한다. 생성 초안과 저장된 일정 모두 연결하며 수동 행 추가도 유지한다. 페이지별 조회, 기존 항목 중복 방지, 100개 한도와 실패 재시도를 제공한다. 저장된 일정의 일괄 추가는 기존 API를 순서대로 사용하므로 원자적 일괄 transaction이 아니며 성공한 항목만 제거하고 실패/미실행/필수 매개변수 미입력 행은 초안으로 남긴다.
- 공통 AutoTextarea를 일정 메모와 MemoEditor에 적용했다. 일정 색상은 워크 위로 이동하고 저장 아이콘 간격을 8px로 좁혔다.
- 새 일정의 09~10 기본값을 제거했다. 원판 아래 짧은 설명, 원판을 밀지 않는 시작/종료 조절 오버레이와 모션, 흰색 선택 호를 적용했다.
- 여러 날 일정의 날짜는 기존 CalendarDatePicker, 시간은 공통 시·분 스크롤 휠을 사용한다. 적용/취소, 방향키/Home/End, 분 단위 보존, 종료 00:00 제한을 유지한다. dialog가 열린 뒤 휠 위치를 다시 정렬해 재열기 시 표시/선택 불일치를 수정했다.
- 이전 작업의 트랙·서버·알림·공통 UI 변경이 이미 있는 작업 트리에서 진행했다. 그 변경은 되돌리지 않았으며 이번 범위는 위 프런트 입력 흐름, 인접 회귀 검사와 문서다. 실제 데이터나 migration은 수정하지 않았다.

## 문서

- SPEC, PRODUCT_GUIDE, TASK_CUSTOMIZATION에 직접 입력·다중 선택·기본 시각 제거·스티커 진입 계약을 반영했다. STATUS는 구현 범위, CODE_MAP은 신규 공통 선택기/목록/자동 높이 입력 경로를 갱신했다.
- DESIGN_SYSTEM에 DateTimePicker와 TaskDirectory를 지정 레퍼런스로 등록했다. 기존 CalendarDatePicker/CalendarGrid, PresetModal/ModalActions, DisclosureSummary, Input/Button, ScheduleColorPicker, StickyWindow와 모션 토큰을 재사용했다.
- 참조/확인 위치: `/design-reference.html#date-time-reference`, `#task-directory-reference`, `#sticky-demo`, `#disclosure-reference`. 실제 구현은 `frontend/src/features/shared/DateTimePicker.tsx`, `ui.tsx`, `frontend/src/features/schedules/TaskDirectory.tsx`, `TimeDial.tsx`, `frontend/src/features/sticky/sticky.css`다.
- CHANGES에 이번 기록을 연결했다. 백엔드 계약과 DB 구조는 변경하지 않아 해당 운영 문서는 수정하지 않았다.

## 검증

- 전체 프런트 테스트: 63개 파일, 352개 테스트 통과. Picker, 일정 생성, 앱 팝업, 자유 스티커 직접 추가, 날짜/시간 선택, 태스크 목록 페이지/중복/한도/오류, 일괄 추가 부분 실패 초안 보존을 검사했다.
- 중간 실패: 이전 기본 시각·네이티브 date/time 입력·이름 사용 버튼을 가정한 일정/앱 테스트가 실패했다. 실제 신규 UI 조작으로 갱신한 뒤 통과했다. 루트에서 실행한 TypeScript 명령은 잘못된 작업 경로로 실패했고 frontend에서 다시 실행해 통과했다. TimeDial 포맷 도구의 일시적 파일 열기 실패는 같은 파일 재실행으로 통과했다. 기존 실패로 분류하거나 숨기지 않았다.
- 브라우저: 데스크톱 다크와 390×844 모바일 라이트/다크에서 공통 캘린더와 휠 표시, 01:59 적용/재열기(실제 scrollTop 44/2596), 그룹별 두 항목 선택을 확인했다. 실제 앱에서는 저장하지 않은 초안으로 이름 직접 입력, 목록 버튼 등장, 색상 위치, 빈 시각, 저장 간격, 메모 6줄 자동 높이(clientHeight/scrollHeight 144px, resize:none)를 확인했다. 시작 조절 열기 전후 원판 손잡이 y=280.725px로 동일했다. 스티커 레퍼런스 창 280px, 헤더 28px, 본문 입력 258.4px로 예약 공간 제거를 확인했다.
- 시각 검증에서 휠 재열기 표시 불일치를 발견해 dialog 레이아웃 이후 정렬하도록 고친 뒤 모바일에서 일치함을 확인했다. 실제 저장/삭제 없이 초안을 닫았다. 실제 터치 기기 관성, 모든 언어/배율 조합, 모션 축소의 수동 시각 검증은 미실시다. 관련 CSS/키보드/기존 모션 회귀는 정적/자동 검사 범위다.
- 최종 `npm run check:frontend` 통과: 문서/기록 게이트, 전체 포맷, ESLint·디자인·구조 검사(126개 모듈, 순환/경계 위반 없음), 63개 파일/352개 테스트, TypeScript와 Vite 배포 빌드. JS 번들 598.76kB로 500kB 청크 경고는 남아 있으며 이번 작업에서 번들 분할은 하지 않았다.
- `git diff --check` 통과. 최종 기록 갱신 후 `npm run check:docs`를 재실행했다. 백엔드는 이번에 수정하지 않아 백엔드 완료 검사를 재실행하지 않았다.
