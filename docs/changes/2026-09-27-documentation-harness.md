# 2026-09-27 변경 기록 복구와 문서 하네스

## 변경

작업 시작 시 HEAD `31c9a01` 대비 기존 프런트엔드·문서 변경과 신규 스티커/공통 UI 파일이 있었다. 이 작업은 기존 제품 코드를 수정하지 않고 현재 diff·새 파일·인접 테스트에 근거해 기록을 복구했다. 과거 대화나 커밋 제목만으로 변경 이유·검증 성공을 추정하지 않았다.

### 기존 변경에서 확인한 내용

- **스케줄 작성·편집**: 태스크 그룹 뒤집기 UI를 이름 입력 행으로 대체했다. 워크 기본 태스크 로드 시 직접 추가한 행을 유지하며 빈 이름 행은 저장 대상에서 제외한다. `TaskNameInput`은 입력 후 200ms 검색·요청 취소·키보드 선택·Enter/blur 확정을 제공한다. 저장된 행은 실행 이름과 매개변수 값을 해당 스냅샷에 반영한다. 새 행은 필수 매개변수가 있으면 값을 입력한 뒤 명시적으로 추가한다. 원형 완료 체크와 상세 편집 진입을 제공한다.
- **스케줄 화면 정리**: 편집 폼 다음에 태스크 목록을 두고 중복 제목·시간대·실행 통계·취소/재개 버튼을 표시하던 부분을 제거했다. 전체 완료 체크는 워크 제목 왼쪽으로 이동했다. 취소/재개 API 자체를 제거한 것은 아니다. 하단 삭제·저장은 배경 없는 텍스트 동작이다.
- **시각 조작**: 여러 날 스케줄은 시계판 없이 직접 날짜·시각을 입력한다. 하루 시각 박스는 선택·강조·확장 후 화살표와 키보드로 설정 단위만큼 조정한다. 기존 자정·역전 제한을 사용한다.
- **공통 모션**: 캘린더 이전 화면의 조기 페이드아웃 및 마지막 프레임 유지, 모달 퇴장 상태 유지, 배경 블러 전환을 적용했다. `usePopupExit`/`usePopupState`는 메뉴·날짜·계정·메모 팝업의 퇴장 동안 마운트를 유지하고 재열기 때 이전 닫기를 취소한다. 축소/비활성 모션에서는 즉시 닫는다.
- **컨트롤·저장 표시**: 항목 종류·태스크 그룹 필터·리마인드 단위·언어 선택을 공통 드롭다운으로 변경했다. 일반/스케줄/태스크 체크에 초록색 획 애니메이션을 적용했다. 저장 중 문구를 줄였지만 요청 중 disabled/aria-busy와 실패 처리는 유지한다. 설정의 상시 자동 저장 안내는 남아 있다.
- **다국어**: 공통 컨트롤·일부 화면에서 언어 변경을 직접 구독하고 디자인 레퍼런스 제목·접근성 이름을 번역했다. 한국어 스케줄 표기를 정리하고 ko/en/ja 스티커·시각·태스크 문구를 추가했다. 푸시 등록 실패는 번역 가능한 오류를 보존하며 일반 요청 fallback도 번역 키를 반환한다.
- **스티커 메모**: `features/sticky/`에 자유 메모·날짜·스케줄 비모달 창, 이동/크기 조절/최소화/닫기/다시 열기/영구 삭제와 디자인 데모를 추가했다. 저장 키는 계정별 `preset.stickies.<accountId>`이며 서버 동기화하지 않는다. 기존 일정·실행 API를 재사용하고 `schedules-changed`, focus, online에서 갱신한다. 설정에서는 숨기며 데이터 초기화 성공 시 일자·스케줄 창을 정리하고 자유 메모는 유지한다.
- **회귀 테스트**: 위 UI·번역·팝업 모션·시간대 변경에 맞춰 기존 인접 테스트를 갱신하고 `ScheduleTaskRows`, `usePopupExit`, 스티커 테스트를 추가한 상태였다.
- **작업 중 추가로 확인한 스티커 변경**: 공유 작업 트리에 `StickyTray`와 관련 창·상태·CSS·번역 변경이 추가됐다. 최소화는 제목 막대 대신 우하단 보관함에 수납하며 위로 펼쳐지는 목록에서 복원한다. 상단바와 가이드는 hover/활성 시 표시하고 스케줄 구분색을 반영한다. 크기 조절은 좌하단 손잡이에서 위쪽·오른쪽 가장자리를 유지한다. 함께 갱신된 기준 문서와 제품 안내를 보존하고 이 기록에도 반영했다.

### 이번 작업에서 추가한 강제 장치

- AGENTS에 편집 전 최신 문서 확인, 모든 변경의 동일 작업 내 기록, 최종 기록 링크·검사 결과 보고를 완료 조건으로 명시했다.
- `docs/CHANGES.md`와 작업별 상세 기록, 기록 본문과 파일 내용을 연결하는 `docs/change-ledger.json`을 도입했다. 코드 외 테스트·설정·문서도 대상이다.
- 기록 게이트는 기존 문서를 한 번 수정한 것만으로 다음 코드 변경이 통과하지 않도록 현재 파일 해시를 비교한다. 신규·삭제·이동·스테이징·CI 커밋 범위를 검사한다.
- `check:docs`, 양쪽 완료 검사, CI documentation job에 게이트를 연결했다. 실제 임시 Git 저장소를 사용하는 회귀 검사를 추가했다.
- 프로젝트 Codex 훅은 시작·프롬프트마다 문서와 Git 상태를 전달하며 세션 시작 HEAD를 임시 파일에 기억한다. 종료 때 세션 전체 변경을 검사해 작업 중 커밋한 변경도 확인한다. 문서나 해시를 자동 갱신하지 않는다.

## 검증

- 최초 제품 상태: `npm run check:frontend` 통과(format, lint/design, 51개 파일·251개 테스트, TypeScript/Vite build). 앱 코드를 이번 작업에서 변경하지 않았다. Vite의 500kB 초과 chunk 경고가 남아 있으며 오류는 아니다.
- 공유 작업 트리의 스티커 보관함 변경 반영 후 `npm run check:frontend` 재실행: 새 precheck 문서 게이트는 통과했으나 `frontend/src/features/sticky/sticky.css`의 Prettier 검사에서 실패했다. 따라서 이 후속 상태의 lint/test/build는 해당 명령에서 실행되지 않았다. 다른 작업의 CSS를 이 문서 작업에서 덮어쓰지 않았고 최초 검증을 최신 제품 상태의 합격으로 간주하지 않는다.
- 하네스: `npm run test:harness` 9개 통과. 실제 설치한 훅 명령을 하위 폴더에서 호출하여 문서 전달·미기록 차단·기록 후 허용·커밋 후 차단을 확인했다. `npm run check:docs`에서 문서 링크와 파일별 기록 검사가 통과했다.
- 첫 하네스 테스트는 샌드박스의 자식 프로세스 `spawn EPERM`으로 실행되지 않았다. 허용된 권한으로 재실행한 위 테스트는 통과했다. 제품/테스트의 실패로 분류하지 않는다.
- 기록 생성·문서 검사도 샌드박스의 `spawnSync git EPERM` 때문에 권한 승인 후 실행했다. 원격 CI 자체는 실행하지 않았다.
- 백엔드 코드는 변경하지 않아 백엔드 전체 검사는 실행하지 않았다. 브라우저 수동 조작·실제 DB/푸시 전달 검증도 이번 작업 범위에 포함하지 않았다.
- Codex 훅 파일 설치와 스크립트 회귀 검사는 실제 앱에서 훅 신뢰가 승인되어 실행됐다는 뜻이 아니다. 새 세션에서 프로젝트·훅을 신뢰해야 한다. 원격 CI 실행과 branch protection 설정도 로컬 검사와 구분한다.
