# 병행 알림 작업의 진행 중 변경 기록 복구

## 변경

- 저장 표시·시간 원판 수정의 종료 훅 이후, 같은 작업 폴더에서 별도 알림 작업이 계속 수정되어 기록이 누락됐다. 이번 후속 작업은 소스 확인과 문서 복구만 수행했으며 알림 기능을 새로 구현하거나 완료 승인한 것이 아니다. 기존 UI 수정은 [원래 기록](2026-09-27-save-feedback-dial-popup.md)을 따른다.
- routes/schedules의 reminders는 Query를 서비스에 전달한다. 서비스는 include의 쉼표 구분 UUID를 최대 200개 검증하고, 소유자·활성 상태·리마인드 사용 조건 안에서 지정 일정을 시작 이후에도 조회한다. 응답에 track_id·reminder_version이 추가됐다. 기본 조회의 시작 전 조건은 유지한다.
- api/reminders는 선택적 include를 중복 제거하여 전달하고, 공통 isReminder로 응답/로컬 저장 항목을 검증한다. reminderInbox는 계정별 localStorage 키, 버전별 중복 억제, 확인/재알림 시각, 30일·200개 보존 및 서버 응답 대조를 정의한다.
- 추가 확인된 NotificationMenu/notifications.css는 미확인 개수·목록·개별/전체 확인·일정 링크·재알림 시각을 표시한다. ActionIcon의 notifications 도형, AnchoredPopup의 선택적 width(기본 280), ko/en/ja Notifications 번역이 추가됐다. 소스 확인 시 NotificationMenu는 아직 앱의 호출자가 없었다. 이 기록은 통합 완료나 UI 검증을 의미하지 않는다.

## 문서

- CHANGES에 복구 기록을 연결하고 CODE_MAP에 진행 중 소스 위치를 추가했다. STATUS에는 미완료 범위를 명시한다.
- SPEC의 기존 리마인드 계약과 비교했다. include 예외는 아래와 같이 구현 관찰로 기록하며, 진행 중인 보관/확인/재알림 UX를 확정 요구로 바꾸지 않는다. 최종 계약 및 WEB_PUSH 문서 동기화는 별도 알림 작업 완료 시 필요하다.
- 알림 UI를 이 작업에서 수정하지 않았으므로 디자인 레퍼런스와 시각 검증을 완료했다고 주장하지 않는다.

## 검증

- 관련 소스와 diff를 읽고 기존 변경을 보존했다. 이 후속 작업에서 백엔드 실행 검사·알림 통합 테스트·빌드를 수행하지 않았다.
- 원래 UI 작업의 마지막 전체 검사는 359개 테스트 통과 후 당시 Toast 번역 키 누락으로 빌드 실패했다. 이후 키가 추가된 것은 확인했지만 재빌드 성공으로 소급하지 않는다.
- 최종 기록 연결 후 check:docs로 경로·기록 최신성을 검사한다. 병행 수정이 이후 다시 발생하면 그 변경은 이 검증 범위에 포함되지 않는다.
