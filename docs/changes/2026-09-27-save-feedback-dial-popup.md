# 저장 표시·중복 완료 표시와 시간/팝업 동작 수정

## 변경

- 사용자 요청 5개에 따라 메모/태스크 저장 성공, 설정 자동 저장 배지, 저장 중 번역·레퍼런스 예시와 저장 아이콘 반복 점멸을 제거했다. 동시 요청 잠금·오류·재시도·초안 보존은 유지하며 저장 방식 자체는 변경하지 않았다.
- 메모 팝업/공통 모달의 바깥 닫힘은 pointerdown 시작점으로 판단한다. 메모 저장 실패로 차단한 바깥 누르기의 후속 click은 기존처럼 차단한다. 내부 드래그의 후속 click에는 닫힘을 연결하지 않는다.
- Today 요약 완료 수 옆 상태 원과 일간 카드/실행의 중복 완료 상태 문구를 제거했다. 취소·진행 중·건너뜀과 태스크 수, 시계 범례는 의미가 달라 유지한다.
- TimeDial의 선택 호를 길이/회전 가능한 circle로 바꾸고 손잡이·레이블·44px 조작 영역을 같은 460ms 회전으로 연결했다. 직접 드래그에는 지연이 없다. 시작/종료 박스 내부 화살표는 grid 행 높이로 펼치고 상위 행은 공간을 예약한다. 일정 모달 외곽 높이는 뷰포트 내에서 고정하고 모바일 details 본문은 높이/투명도를 전환한다. CSS 토큰과 기존 앱/OS 축소 설정을 따른다.
- 이전 작업의 대규모 미커밋 변경을 유지했다. 시작 시 소스/문서 임시 사본을 만들어 이번 변경과 비교했다. 백엔드 구현은 수정하지 않았다.

## 문서

- SPEC, STATUS, DESIGN_SYSTEM, PRODUCT_GUIDE, TASK_CUSTOMIZATION, SETTINGS를 현재 계약으로 갱신했다. 경로 신규/삭제가 없어 CODE_MAP은 유지한다. CHANGES에 연결했다.
- 지정 레퍼런스 /design-reference.html#date-time-reference, #completion-reference와 실제 TimeDial, PresetModal/ModalActions, MemoPopover, ui.tsx를 읽고 기존 표현을 확인했다. 레퍼런스에 실제 시간 펼침을 연결하고 저장 중 예시를 제거했다.

## 검증

- 최초 선택 6개 파일/32개 테스트 통과. 전체 첫 실행은 354개 통과·새 pointer 회귀 1개 실패: 테스트 환경의 PointerEvent 좌표 지원 차이로 MouseEvent 기반 pointerdown fixture로 수정 후 해당 5개 테스트 통과. 기존 실패로 분류하지 않는다.
- 실제 수정 모달에서 1080×648 크기, 원판 420px, 화살표가 박스 내부에 포함됨을 확인했다. 내부→외부 드래그에서도 모달이 유지됐다. 시간 변경 초안은 저장하지 않았다.
- 첫 전체 check:frontend는 포맷·lint·디자인/구조를 통과했으나 검사 중 외부에서 수정된 Calendar 전환 테스트 1개가 실패했다. 같은 테스트는 직전 전체 테스트에서 통과했으며 이번 요청의 구현에서 Calendar 전환을 수정하지 않았다. 병행 작업이 테스트를 보강 중인 것을 확인했다.
- 검사 도중 별도 작업에서 App/PresetWorkspace/HorizontalNavigation/WorkspaceHeader/워크·태스크 목록과 캘린더 전환이 변경됐다. 프리셋 목록의 공통 탐색 래퍼·가로 표시선/페이지 모션·제목 없는 하위 목록 변경을 소스로 확인했다. 이 작업의 기능 구현으로 주장하지 않으며 변경을 보존한다. 초기 변경 파일 자동 수집 포맷 실행에 이 파일들도 포함됐다. 이후 포맷은 명시적 이번 파일만 대상으로 한다.
- 모바일 390×844에서 시간 접힘 모달 366.4×820, 가로 문서 폭 390px을 확인하고 펼침을 시각 확인했다. 병행 변경의 HMR로 최종 펼침 치수 재측정은 중단되어 데스크톱 크기 실측과 구분한다. 임시 뷰포트는 원복했다.
- 레퍼런스 키보드 시간 변경에서 15도 목표 회전에 대해 중간 실제 matrix가 약 0.89도, transition 0.46초인 것을 측정해 보간을 확인했다. 실제 터치 기기·OS 모션 축소 설정의 수동 전환은 미검증이다. CSS 전역 축소 규칙은 유지한다.
- 브라우저 모바일 전환 직후 수정 링크 검증 중 좌표가 이동하여 ddk의 두 번째 asdf 완료 체크가 잘못 눌렸다. 즉시 같은 체크로 미완료를 복원하고 태스크 0/2와 두 태스크 pending을 UI/API로 확인했다. 실행 API의 최초 시작 시각·updated_at은 이 조작으로 갱신됐을 수 있으며 직접 DB를 수정하지 않았다. 실제 데이터를 fixture로 사용하지 않았지만 이 오조작은 없었다고 기록하지 않는다. 시간 편집 초안은 저장하지 않았다.
- 병행 수정 중 두 번째 전체 실행은 App의 새 전환 테스트 1개 실패(357개 통과), 빌드는 새 가로 탐색 레퍼런스 배열 인덱스의 undefined 가능성으로 실패했다. 공통 편집 파일인 design-reference의 기본값을 day로 명시한 뒤 빌드가 통과했다. 실패를 성공으로 소급 기록하지 않는다.
- 최종 관련 검사: 11개 파일 66개 테스트 통과. TypeScript/배포 빌드 통과. 기존 500kB 초과 번들 경고 유지. 저장 표시/점멸/work-state-dot 잔존 검색과 git diff --check 통과. 최종 기록 연결 후 check:docs 및 전체 완료 검사를 실행한다.
- 개발 서버 http://127.0.0.1:15173/와 API 3000을 유지하고 앱/시간 레퍼런스 탭을 남겼다. 검증 화면은 저장소 밖 visualizations의 time-dial-fixed.png에 저장했다.
- 병행 코드 검토 범위: Sidebar 전환을 Calendar ref로 연결, 월/연 이전 요약을 다음 조회까지 유지, 로딩 표시 절대 위치, 전환 복제본의 zoom/폰트 보존 및 양쪽 애니메이션 종료 후 정리, 관련 Calendar/App/HorizontalNavigation 회귀 추가. 변경의 작성 주체는 별도 작업이며 여기서는 현재 내용을 확인/보존한 사실과 실제 검사 결과만 기록한다.
- 마지막 전체 검사는 병행 App.test.tsx의 포맷만 남아 중단됐다. 추가된 테스트 전체를 읽고 해당 파일만 포맷한 뒤 재검사한다.
- 전체 check:frontend가 포맷·lint·디자인/구조·358개 테스트·TypeScript·빌드까지 통과했다. 최종 검토에서 요약 체크 옆 완료 문구도 중복임을 확인해 숨기고 재검사한다.

- 최종 결과: 마지막 Today 회귀 16개 통과, 전체 64개 파일/359개 테스트와 포맷·lint·디자인/구조 통과. 마지막 전체 명령의 빌드 단계는 검사 도중 새로 들어온 Toast의 Notifications.snooze/minutes/hours 번역 키 미등록으로 실패했다. 직전 전체 빌드는 성공했으나 최신 빌드 성공으로 주장하지 않는다. 알림 재예약 작업은 이번 요청 범위 밖이며 수정 중인 로직을 되돌리지 않았다.
- 누락 기록 복구 범위: 검사 중 추가된 Toast의 선택적 onSnooze 콜백/5·10·30분 및 1·3시간 드롭다운, 퇴장 후 콜백, toast.css의 아래 방향 퇴장 변수 80px을 현재 소스로 읽었다. 별도 알림 작업의 진행 중 변경으로만 기록하며 이번 작업의 기능/검증 완료로 포함하지 않는다. 탐색 작업의 별도 [기록](2026-09-27-navigation-motion.md)을 읽고 해당 문서 변경을 그 기록에 연결했다.
