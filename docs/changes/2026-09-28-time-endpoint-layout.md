# 시간 조절 영역 배치 교정

## 변경

- 기존 선택적 시간 작업의 중복 시간 버튼·날짜까지 감싼 강조 영역을 교정했다. TimePicker가 큰 시각 표시 자체를 트리거로 재사용한다. 첫 클릭은 화살표를 펼치고 두 번째 클릭은 상세 시·분 휠을 연다. 시간 지정 해제를 펼침 영역에서 바로 제공한다.
- 여러 날 입력은 시작/종료 fieldset 안에 날짜와 시각을 배치한다. 부터/까지 레이블은 강조 영역 밖이며 영어는 위, 한국어·일본어는 아래다. 섹션과 내부 간격을 공통 토큰으로 맞추고 데스크톱 좌우·모바일 상하 배치를 유지한다.
- 레퍼런스는 여러 날에 걸친 스케줄 예시 하나로 통합한다. 별도 원판 데모를 제거하고 TimeEndpoint에서 공통 스타일을 직접 로드하여 제품과 레퍼런스를 일치시킨다.
- 기존 macOS 설정·자정 통과·선택적 시간 저장 작업을 보존했다. 이번 변경은 프런트 표시·상호작용·인접 테스트·문서에 한정하며 DB/API/당일 시계판 저장 동작은 변경하지 않았다.

## 문서

- SPEC과 DESIGN_SYSTEM의 시간 버튼 클릭 단계·섹션·외부 레이블 계약, STATUS의 구현 범위를 갱신하고 CHANGES에 연결했다. CODE_MAP은 경로 변경이 없어 유지했다.
- 편집 전 DESIGN_SYSTEM 및 `/design-reference.html#date-time-reference` 상태와 실제 TimeEndpoint/TimeDial/DateTimePicker/Button/ActionIcon을 읽고 확인했다. 동일 공통 휠·팝업·화살표·모션을 재사용한다.

## 검증

- 기존 인접 테스트 44개 통과. 단계별 클릭·단일 시각 표시·외부 레이블·직접 해제 회귀를 추가했다. 첫 전체 프런트 실행은 392개 통과·1개 실패였다. App의 기존 단일 클릭 휠 열기 기대값을 새 두 단계 동작으로 수정했다. 최종 `npm run check:frontend` 통과: 포맷·lint·디자인/구조 검사·69개 파일 393개 테스트·TypeScript·빌드. 기존 JS 청크 500kB 초과 경고는 남아 있다.
- 브라우저에서 첫 클릭 화살표 표시, 두 번째 클릭 상세 휠 열림, 데스크톱 좌우 배치를 확인했다. 원판 데모 제거 후 레퍼런스 스타일 누락을 발견해 TimeEndpoint의 직접 스타일 import로 수정했다. 390×844 모바일에서도 상세 휠 닫기·직접 해제 후 미지정 복귀를 확인했다. 해제 뒤 큰 시각 버튼으로 포커스를 돌려준다.

- 모바일 최종 화면에서 단일 큰 시간, 하단 화살표·해제 버튼, 강조 영역 밖 부터/까지와 시작/종료 간격을 확인했다. 임시 뷰포트를 복원했고 레퍼런스·생성 화면과 개발 서버를 유지한다. `/api/health` 정상 응답. 실제 터치 기기 관성은 미검증이다. 최종 diff/공백을 검토하고 기록 갱신 후 문서 게이트를 재실행했다.
