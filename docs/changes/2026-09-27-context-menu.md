# 콘텐츠 컨텍스트 메뉴

## 변경

- 우클릭/550ms 길게 누르기 메뉴와 투명 native modal top layer, 화면 경계 보정, 공통 아이콘/모션, 키보드 탐색·포커스 복귀를 추가했다. 이동/스크롤/취소에서 터치 타이머를 정리한다. 미지정 우클릭과 휠클릭은 차단하고 휠 스크롤은 보존한다.
- Today/일간 일정·태스크, 일정 검색, 프리셋 목록, 월간 일정 막대, 스티커 창/일정의 기존 버튼에 명시적 메타데이터를 연결했다. 메뉴는 기존 버튼/링크를 실행하므로 삭제 확인·메모 저장·오류 처리·스티커 기능을 복제하지 않는다. 색상 변경과 모바일 일정 메모는 기존 편집 창으로 연결한다.
- 기존 DeleteButton의 실패 오류를 해당 콘텐츠로 portal 표시하여 숨겨진 모바일 바로가기에서도 오류를 읽을 수 있게 했다. 오래 누른 뒤 손을 떼는 경우에도 후속 클릭을 차단하도록 해제 시점을 기준으로 보호한다.
- 모바일 일정 액션은 숨긴 DOM으로 유지하여 같은 핸들러를 이용한다. 한국어/영어/일본어 문구와 실제 공통 컴포넌트를 사용하는 디자인 레퍼런스를 추가했다.
- 작업 시작 전 광범위한 트랙·UI·문서 하네스 변경이 있었다. 기존 변경은 기존 기록에 속하며 이번에는 콘텐츠 경계/액션 메타데이터, 모바일 액션 유지와 신규 메뉴만 추가했다. 기존 파일 전체 diff에서 선행 모션·프리셋 DropdownSelect·완료 공통화·캘린더 요약 변경을 확인하고 보존했다. 백엔드/API/DB는 수정하지 않았다.

## 문서

- SPEC에 입력·메뉴·기존 액션 위임 계약, DESIGN_SYSTEM에 공통 레퍼런스와 확장 규칙, STATUS에 구현 범위, CODE_MAP에 경로를 추가했다. CHANGES에 연결했다.

## 검증

- 선택 테스트: 2개 파일·8개 테스트 통과. 대상 경계, 기존 삭제 확인, 키보드, disabled, 미지정 우클릭/휠클릭, 터치 취소/후속 클릭 차단, 모바일 연결을 확인했다.
- 초기 테스트 실행은 샌드박스 esbuild spawn EPERM으로 시작하지 못했다. 승인된 재실행에서 발견한 테스트 이벤트 호출과 번역 키 형식 오류를 수정하고 통과했다.
- 1차 전체 프런트 검사 통과: 포맷·lint/디자인/구조 검사, 60개 파일·329개 테스트, TypeScript·Vite 빌드. 이후 삭제 오류 표시와 긴 터치 후속 클릭 회귀를 보완한 최종 `npm run check:frontend`도 통과했다(60개 파일·330개 테스트, 포맷·lint/디자인/구조·TypeScript·빌드). Vite의 기존 500kB 초과 chunk 경고는 남아 있다.
- 실제 브라우저 레퍼런스에서 우클릭 → 메뉴 → 기존 편집 모달 연결, Escape 닫기와 390px 메뉴 경계 보정을 확인했다. 실제 터치 기기는 미검증이며 터치 이벤트는 자동 테스트로 검증한다. 실제 DB는 사용하지 않았고 백엔드 검사는 범위 밖이다.

- 최종 diff 공백 검사 통과. 문서 링크·변경 기록 게이트는 프런트 완료 검사에서 통과했으며 최종 결과 문구를 기록한 뒤 `record:change`와 `check:docs`를 다시 실행한다.
