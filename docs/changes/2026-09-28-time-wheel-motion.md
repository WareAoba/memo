# 시·분 직접 선택 휠 모션과 팝업 안정화

## 변경

- 사용자가 말한 시간 다이얼은 DateTimePicker의 시·분 휠이었다. 앞선 [원판 수정](2026-09-28-time-dial-motion-bounds.md)은 대상을 잘못 이해한 작업이며 해당 턴에서 추가한 TimeDial·테스트·schedules.css 변경만 정확히 철회했다. 그 이전 변경은 유지하고 과거 기록은 삭제하지 않았다.
- TimeWheel이 값 변경마다 scrollTop을 즉시 덮어쓰던 방식을 초기 정렬/명시 선택/스크롤 확정으로 분리했다. 클릭·키보드는 smooth scroll, 직접 스크롤은 관성과 스냅을 유지하며 각 숫자는 실제 스크롤 위치에 따라 회전·가장자리 페이드한다. 앱/OS 모션 축소는 즉시 정렬·회전 생략을 사용한다.
- 휠은 고정 96×220px 크기와 layout/paint containment로 숫자 스타일 변화와 외곽 배치를 분리한다. 공통 팝오버 배치 관찰자는 메뉴 내부 스크롤을 무시하고 외부 스크롤·resize는 계속 따라간다.
- 적용 전 초안, 분 정밀도, 종료 00:00 제한, Escape/취소·포커스 복귀는 유지한다. 서버/저장 데이터는 변경하지 않았다.

## 문서

- 최신 STATUS·CODE_MAP·CHANGES·DESIGN_SYSTEM, SPEC 시간 입력 절, 기존 시간 드롭다운/UX 개선 기록과 관련 소스 전체를 확인했다. 지정 레퍼런스는 /design-reference.html#date-time-reference의 시간 버튼이 여는 DateTimePicker/AnchoredPopup/MenuSurface다.
- SPEC·DESIGN_SYSTEM에 직접 선택 휠의 모션/크기 계약을 명시했다. 기능 범위나 코드 경로는 동일하여 STATUS·CODE_MAP은 유지한다. 기존 공통 CSS 변경은 그대로 보존했다.

## 검증

- 선택 검사 3개 파일 20개 통과: 원판 철회 회귀, 휠 smooth/축소 모션 선택, 스크롤 확정·초안 보존, 팝업 내부 스크롤 무시/외부 스크롤 추적을 포함한다.
- 390×844 레퍼런스에서 숫자 클릭·Home/End 이동과 스크롤 정렬을 확인했다. 23→00 변경 직후 선택값은 00, scrollTop은 1012였고 이후 0에 도달하여 즉시 점프 대신 보간함을 확인했다. 선택 변경 전후 팝업은 280×373.6px·동일 좌표를 유지했다. 숫자의 원근 회전·페이드도 시각 확인했다.
- 1280×900에서도 시·분 변경 전후 팝업 280×373.6px, 각 휠 96×220px 및 위치 유지 확인. Escape 후 재열기는 적용하지 않은 초안을 버리고 기존 값으로 복귀했다. 임시 뷰포트는 원복했으며 5173 서버와 시·분 휠을 연 레퍼런스 탭을 유지한다. 확인 이미지는 저장소 밖 visualizations/time-wheel-fixed.png다.
- 전체 `npm run check:frontend` 통과: 포맷·lint·디자인/구조·68개 파일 382개 테스트·TypeScript·빌드. 기존 500kB 초과 청크 경고는 유지된다. 최종 diff 검토·기록 연결 후 `npm run check:docs` 통과(71개 Markdown 경로·284개 변경 파일 기록).
- 실제 터치 기기 관성 및 OS 모션 설정 직접 변경은 미검증이다. 모션 축소의 즉시 정렬은 회귀 테스트로 검증했다. 백엔드 변경은 없어 백엔드 검사는 재실행하지 않았다.
