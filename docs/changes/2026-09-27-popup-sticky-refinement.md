# 콘텐츠 메뉴와 스티커 모션 후속 수정

## 변경

- 기존 콘텐츠 컨텍스트 메뉴·트랙·펼침 통일 작업 위에서 사용자가 요청한 후속 UI를 수정했다. 기존 다른 작업과 백엔드·실제 데이터는 보존했다.
- 작업 중 함께 반영된 테마·상태 토큰·종류 입력·토스트 변경은 [별도 레퍼런스 UI 기록](2026-09-27-reference-ui-fixes.md)의 범위다. 공유 파일의 최종 diff를 읽어 해당 변경과 이번 팔레트/모션 변경을 구분했고 그대로 보존했다.
- 메뉴의 시각적 제목·테두리를 제거하고 맨 위에 기존 ScheduleColorPicker를 표시한다. ContextMenuSlot은 원래 기능 소유의 컨트롤을 portal로 연결하며 메뉴에 도메인 저장 로직을 넣지 않는다. ScheduleContextColor는 기존 saveSchedule·변경 알림·오류 표현을 재사용한다. Today·일간·검색·월간 막대·스티커 일정에 연결하고 저장 중 중복 요청, 실패 재시도와 원래 링크로의 클릭 전파를 방지한다.
- MenuSurface·메모 팝오버의 진입을 popupMotion으로 통일해 포인터 원점에서 확장/축소한다. 메뉴 제목은 접근 가능한 이름으로만 유지한다. 입력형 태스크 목록도 같은 표면을 사용한다. 중복된 보관함/메모 CSS 애니메이션은 제거했다.
- 공통 usePopupState가 퇴장 애니메이션을 DOM 제거 이전에 cancel하던 순서를 수정했다. 트랙 드롭다운·보관함·계정·종류·태스크 이름 입력의 같은 경로를 수정했다. 날짜 선택·메모·컨텍스트 메뉴의 직접 usePopupExit 및 PresetModal도 확인했다. PresetModal은 이미 마지막 프레임을 unmount까지 유지해 별도 변경하지 않았다. 빠른 토글은 닫힘을 취소하며 보관함 복원은 퇴장 후 실행해 빈 목록이 잠깐 표시되는 문제도 막는다.
- 스티커 생성/삭제는 공통 토큰 기반 확장/축소·페이드다. 닫기와 목록 삭제는 저장 상태에서 즉시 제거하고 비대화형 스냅샷만 퇴장시킨다. 최소화/복원 지니와 스냅샷 생성 코드를 공유한다. 이전 복원 표시를 새 생성/닫기에서 제거하고 진입 효과는 mount마다 한 번만 실행한다. 서버 DB의 일정은 건드리지 않으며 스티커 저장 위치는 기존 브라우저 localStorage다. 이미 과거 버전에서 보관된 closed 기록을 일괄 삭제하는 migration은 하지 않는다.
- UI 편집 전 지정 레퍼런스 /design-reference.html의 DropdownSelect·MenuSurface/MenuOption·DisclosureSummary·ScheduleColorPicker·StickyDemo와 실제 구현을 확인했다. 신규 직접 팔레트 패턴을 같은 레퍼런스에 먼저 연결했다.

## 문서

- SPEC의 닫기/보관·색상 직접 선택·모션 계약, PRODUCT_GUIDE의 닫기 안내, DESIGN_SYSTEM의 공통 패턴, STATUS의 구현 범위, CODE_MAP의 신규 연결 경로를 갱신했다. CHANGES에 연결했다.

## 검증

- 선택 테스트 4개 파일 28개 통과: 색상 API 실패/재시도·클릭 전파·키보드, 퇴장 제거 순서, 스티커 기록 삭제/재생성·지니 회귀, 스냅샷과 모션 축소. 이후 빠른 토글 회귀를 추가했으며 최종 전체 검사로 재확인한다.
- TypeScript 검사 통과. 처음 루트에서 실행한 tsc 명령은 tsconfig 경로 오류로 실행되지 않아 frontend 디렉터리에서 재실행했다. 중간 편집 스크립트의 문법 오류는 파일 적용 전에 실패했으며 수정 후 재실행했다.
- 최종 npm run check:frontend 통과: 문서 링크·변경 기록 게이트, 포맷, ESLint·디자인·구조 검사, 61개 파일 338개 테스트, TypeScript·Vite 빌드. 기존 500kB 초과 번들 경고는 남아 있다. 빠른 토글 회귀도 전체 실행에 포함됐다. 백엔드는 수정하지 않아 재검사하지 않았다.
- 최종 git diff --check 통과. 변경 기록 결과를 반영한 뒤 record:change와 check:docs를 재실행한다.
- 브라우저 레퍼런스에서 제목/테두리 없는 상단 팔레트, 색상 직접 선택, Escape 닫기, 최소화/보관함 복원, 닫기 후 빈 메모 생성을 확인했다. 기본 데스크톱과 390px 모바일 폭의 메뉴 경계·밝은/어두운 표면을 확인하고 임시 뷰포트를 복원했다. 포인터의 좌상단 원점과 공통 scale 퇴장 속성을 DOM에서 확인했다. 개발 중 HMR 이후 남아 있던 메뉴 DOM은 새로고침 후 한 개만 렌더됨을 확인했다. 브라우저 읽기 API의 getAnimations는 미지원이라 프레임별 관측은 못 했고 타이밍/정리는 자동 테스트로 확인했다. 실제 DB 쓰기와 실제 터치 기기는 미검증이다.
