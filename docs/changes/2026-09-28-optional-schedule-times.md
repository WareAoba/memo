# 선택적 일정 시각과 순차 입력

## 변경

- 새 일정은 시간 미지정 또는 시작만 지정해도 저장한다. API는 문자열 호환을 유지하며 생략/빈 문자열을 미지정으로 처리한다. 종료만 있는 입력은 거부한다. 시작이 없으면 리마인드를 사용할 수 없고, 입력에서 시작 해제 시 종료·리마인드도 해제한다.
- TimeDial 상단 박스를 TimeEndpoint로 공유하고 ScheduleDateRange에서 재사용한다. 처음 하나의 레이블 없는 시간 입력을 표시하고 지정 후 두 번째 입력과 부터/까지를 표시한다. 영어 레이블은 위, 한국어·일본어는 아래에 둔다. 날짜 범위는 데스크톱 좌우·모바일 상하 배치다. 기존 DateTimeSection을 대체한다.
- 미지정은 공통 연한 지정 없음 텍스트로, 시작만 지정한 경우는 시각+부터로 편집 요약·목록·검색에 표시한다. Today 시계판은 미지정 일정을 제외하고 시작만 있는 일정은 시작일에 강조색 막대 하나로 표시한다. 종료가 없으면 시각 경과만으로 초과 처리하지 않는다.
- 새 migration은 일정 및 스냅샷/태스크/항목/사진/푸시 전달 행을 보존하며 시간 CHECK만 확장한다. 소유자·트랙·revision·리마인드 버전·인덱스/트리거와 transaction 경계를 보존한다. 적용된 migration은 수정하지 않았다.
- 작업 시작 시 기존 macOS 개발 설정과 자정 통과 일정 작업의 변경을 확인·보존했다. 이번에는 선택적 시간 저장과 공유 UI/표시/테스트 및 기준 문서를 추가 변경했으며 이전 기록은 유지했다.

## 문서

- SPEC의 API·시간 입력·Today 시계판 계약, STATUS 구현 범위, CODE_MAP 신규 컴포넌트/migration 위치, DESIGN_SYSTEM 공유 박스·반응형/언어별 상태를 갱신했다. CHANGES에 이 기록을 연결했다.
- UI 편집 전 DESIGN_SYSTEM 지정 `/design-reference.html#date-time-reference`, 실제 TimeDial·DateTimePicker·공통 Button/화살표를 확인했다. 신규 공유 컴포넌트도 같은 레퍼런스에서 렌더한다.

## 검증

- 일정 서비스 선택 검사: 20개 통과. 미지정 생성·시작만 수정·해제·종료만/잘못된 시각/미지정 리마인드 거부를 검증했다. 격리된 DB에서 기존 스냅샷 그래프·사진·푸시 전달·트랙 revision·모든 인덱스/트리거의 이관 전후 동일성, 외래 키, 이관 후 revision 동작을 확인했다. 실제 데이터는 테스트에 사용하지 않았다.
- 프런트 선택 검사와 TypeScript/빌드 통과. 첫 선택 검사에서 이전 두 입력/필수 시간 테스트 16개가 실패해 순차 입력·선택 시간 계약에 맞춰 갱신했다. 첫 전체 실행은 387개 통과·2개 실패(App 입력 순서와 Today 요약의 시간 구분자 기대값)하여 해당 기대값을 수정했다. 최초 포맷 명령은 루트 기준 경로 누락으로 실패한 뒤 정확한 변경 파일 경로로 실행했다.
- 실제 브라우저 레퍼런스에서 1280×900 좌우, 390×844 상하 배치와 첫 시각 지정 후 두 번째 입력·옅은 미지정·한국어 하단 레이블을 확인했다. 제품 생성 모달에서도 1280×900 좌우 배치, 390×844 상하 배치·접힌 요약·종료 조절 박스 펼침을 확인했다. 임시 뷰포트는 복원했고 생성 초안과 레퍼런스 탭을 유지했다. 실제 터치 기기 관성은 미검증이다.

- 최종 `npm run check` 통과: 문서/변경 게이트, Rust 포맷·clippy·전체 테스트·빌드, 프런트 포맷·lint·디자인/구조 검사·69개 파일 391개 테스트·TypeScript·빌드. 기존 JS 청크 500kB 초과 경고는 남아 있다.
- 제품 확인 중 백엔드가 실행 중이지 않아 `npm run dev:backend`로 다시 가동했다. 새 migration 적용 후 `/api/health` 정상 응답을 확인했다. 프런트/백엔드와 http://127.0.0.1:15173/#/schedules/new 생성 모달 및 http://127.0.0.1:15173/design-reference.html#date-time-reference 를 유지한다. 실제 사용자 일정을 생성/수정/삭제하지 않았다.
- 최종 diff와 공백 오류를 검토한 뒤 기록을 갱신하고 문서 검사를 다시 실행했다.
