# 2026-09-27 구조 감사 후속 2차: 일정 갱신·조회 공유·캘린더 요약

## 변경

[감사 보고서](2026-09-27-code-structure-audit.md)의 권장 순서 2 중 남아 있던 일정 갱신/조회 구조를 개선했다. 생성 초안 분리는 [1차](2026-09-27-schedule-state-refactor.md)에서 완료한 기존 작업이다.

- 공통 HTTP client의 URL 기반 이벤트 발생을 제거했다. 일정 API는 파싱한 성공 상세와 ID, 삭제는 ID를 명시적으로 전달한다. 워크·태스크 신규 등록/승격, 초기화 API는 전체 갱신을 명시한다. 오류/잘못된 응답을 성공 알림으로 전달하지 않는다.
- 같은 상세 ID 또는 같은 범위/상세 여부의 진행 중 요청을 합친다. 한 호출자의 AbortSignal은 다른 호출자의 조회를 중단하지 않고 마지막 호출자가 떠나면 요청을 취소한다. 성공·실패 완료 결과는 보관하지 않으며 변경 generation 이후 조회는 이전 요청에 합류하지 않는다. 서로 겹치기만 하는 다른 범위와 요약/상세는 합치지 않는다.
- 스티커는 성공 응답을 직접 반영하고, 다른 일정의 변경은 개별 일정 스티커에 영향을 주지 않는다. 날짜 밖 이동·삭제는 목록에서 제거한다. 초기 조회 중 변경과 전체 변경은 재조회하며 늦은 이전 응답을 무시한다. Today·Calendar·Reminders의 기존 갱신/편집 잠금은 유지한다. 모든 화면의 재조회를 없앤 것은 아니다.
- 월/연간 캘린더는 요약 목록, 일간은 선택 날짜의 상세만 읽는다. 상세 없이도 빈 제목을 기존처럼 표시하도록 서버 요약에 entity_name을 추가했다. 이름은 현재 원본 프리셋이 아닌 독립 워크 스냅샷에서 페이지 단위로 읽는다. 소유자 범위·읽기 transaction·정렬·날짜 겹침·revision/최대 3회 재시도를 유지했다.
- 캘린더는 요약과 상세를 구분한 상태로 관리해 월/연 응답을 일간 상세로 사용하지 않으며 성공한 재조회에서 이전 오류를 해제한다. App·시간대·캘린더 테스트의 API mock을 새 조회 경계에 맞췄다.
- 시작 당시 미커밋 UI·다국어·스티커·문서 하네스 및 1차 리팩토링은 기존 작업이다. 수정한 기존 파일의 전체 diff와 새 스티커 파일을 확인하고 이전 변경을 보존했다. DB migration·실제 데이터·CSS 변경은 없다.

## 문서

- SPEC: 요약 응답·화면별 조회·명시적 변경/공유 취소 계약을 추가했다.
- STATUS·CODE_MAP·CHANGES: 2차 구현 범위·새 API 모듈·기록 링크를 반영했다.
- TASK_CUSTOMIZATION·DESIGN_SYSTEM·I18N: 초안/메모 입력·스타일·번역 계약을 바꾸지 않아 수정하지 않았다.
- 감사의 CSS 소유권/시각 검증, App 라우팅 상태, 백엔드 반복 조회/DTO, 미사용 모듈/구조 검사는 후속 범위다. 감사 전체를 완료한 것으로 기록하지 않는다.

## 검증

- 선택 프런트 검사: 5개 파일 66개 테스트 통과. 요청 횟수(동일 동시 조회 2개 → HTTP 요청 1개), 개별/전체 취소, 실패 후 재시도, 변경 후 새 요청, 9종 쓰기 성공 이벤트, 잘못된 응답/실패 무알림, 요약/상세 분리, 스티커 날짜 이동·삭제·이전 응답 무시, 캘린더 조회/오류 복구를 확인했다.
- 최초 선택 검사는 샌드박스 esbuild spawn EPERM으로 시작하지 못했고 권한 확장 재실행으로 통과했다. 환경 실패이며 assertion 실패가 아니다.
- TypeScript: 새 캘린더 상태 union의 onChange 좁히기 누락을 발견해 수정한 후 통과했다. 이번 구현 중 발생한 오류이며 기존 실패로 분류하지 않는다.
- 백엔드 선택 검사: review 빌드 경로의 summaries_keep_snapshot_names_without_task_payloads 통과. 임시 DB에서 빈 제목·원본 이름 변경 후 스냅샷 이름 보존·상세 필드 미포함·동일 revision·응답 크기 감소를 확인했다.
- `npm run check:frontend`: 통과. Prettier·ESLint/design·54개 파일 294개 테스트·TypeScript·Vite build 성공. 기존 500 kB 초과 경고는 남는다(JS 570.78 kB, gzip 173.75 kB).
- `CARGO_TARGET_DIR=backend/target/review`에서 `npm run check:backend`: 통과. 문서 검사·fmt·Clippy(`-D warnings`)·전체 cargo test·build 성공. 감사 때 확인한 기본 경로 실행 파일 잠금을 피한 기존 review 경로이며 실제 데이터를 사용하지 않았다.
- 최종 diff·추가 모듈·기존 파일의 이전 변경을 검토했고 `git diff --check`는 통과했다(기존 문서의 CRLF/LF 정규화 경고만 있음). 기록 명령의 최초 시도는 샌드박스 `spawnSync git EPERM`으로 실패했으며 권한 확장 재실행으로 이번 범위 23개 파일을 연결했다. 양쪽 완료 검사의 문서 게이트에서 Markdown 47개 파일의 링크와 변경 파일 118개 기록 검사를 통과했다. 이 결과 문장 갱신 후 같은 기록 명령과 문서 검사를 다시 수행한다.
- 미검증: 실제 브라우저 시각 검사·렌더 시간·실운영 대규모 성능·실제 DB/사진/푸시 전달·원격 CI. 요청 횟수 회귀와 작은 API fixture의 응답 크기 비교를 실제 기기 성능 향상 수치로 해석하지 않는다.
