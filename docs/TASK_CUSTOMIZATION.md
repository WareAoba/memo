# 태스크 입력칸과 개별 메모

## 제품 흐름

날짜 선택 → 목표(워크) 선택 → 세부 과제(태스크) 선택을 유지한다. 이번 변경은 추천이나 새로운 자동 선택을 추가하지 않는다. 사용자가 선택한 과제의 분량·내용과 기록을 직접 조정한다.

## 입력 문법

- `단어 [n]개 외우기`: 선택 시 n 입력칸이 나타나며 저장 전에 입력한다.
- `단어 [n=5]개 외우기`: 처음 값은 5이며 일정별로 수정한다.
- `[과목=영어] 문제 [개수=10]개 풀기`: 여러 입력칸을 지원한다.
- 같은 이름은 하나의 값을 공유하고, 기본값은 처음 등장한 정의를 사용한다.
- 이름은 영문·한글 완성형·밑줄로 시작하며 이후 숫자도 허용한다. 이름 32자, 값 80자, 태스크 이름 200자 제한이다. 값은 숫자 또는 일반 텍스트이며 수식이나 코드를 실행하지 않는다.
- 문법과 일치하지 않는 대괄호는 일반 텍스트로 유지한다. 입력값을 다시 문법으로 해석하지 않는다.
- 기존에 `단어 5개 외우기`로 저장한 프리셋은 직접 이름을 수정하거나 `[n=5]`로 바꾼 후 사용한다. 기존 일정은 자동 변경하지 않는다.

## 저장

- 프리셋 이름은 문법을 포함한 원본 문장이다.
- `schedule_tasks.name_template_snapshot`에 생성 당시 문장, `parameter_values`에 이번 입력값, `name_snapshot`에 표시할 완성 문장을 보존한다.
- 생성 API의 `task_customizations`는 선택한 프리셋 ID별 `{parameters, execution_notes}`를 받는다. 태스크 추가 API도 같은 필드를 지원한다.
- 실행 PATCH의 `parameters`는 입력값 전체를 교체한다. `name`을 보내면 이번 실행의 문장도 교체한다. 서버가 입력과 최종 길이를 검증하고 전체 작업을 transaction으로 저장한다.
- 이미 존재하는 실행은 migration으로 현재 이름을 보존하며, 메모만 수정할 때는 문장을 재해석하지 않는다.

## 메모 범위와 접근

- 프리셋 목록·상세·선택 후보의 메모는 워크 `general_notes`, 태스크 `default_notes`를 수정한다. 기존 일정에는 소급 적용하지 않는다.
- 일정 조립 중 워크 메모는 `notes`, 선택한 태스크 메모는 `execution_notes` 초안이며 일정 저장 시 함께 저장된다.
- 오늘 요약·실행 카드·일간 캘린더·일정 상세·검색 결과의 메모는 해당 일정에만 저장된다.
- 데스크톱 스케줄 카드 내부 우측에 메모·스케줄 수정 버튼을 함께 배치한다. 메모 유무와 관계없이 평소에는 숨기고, 카드 hover·키보드 focus 시 표시한다. 숨겨진 동안 버튼 공간을 비워두지 않으며, 버튼 표시와 함께 태스크 개수 등 우측 내용을 트랜지션으로 이동한다. 열린 팝업의 버튼은 표시를 유지한다.
- 팝업의 기본 우상단 모서리는 메모 버튼의 중심점에 실제로 겹친다. 다른 모서리로 전환해도 같은 점을 기준으로 한다. 해당 모서리에서 대각선으로 확대하며 앱·시스템의 모션 줄이기 설정을 따른다. 여백이 부족하면 좌우·상하를 독립적으로 전환하고, 폭·높이를 제한한다. 스크롤과 창 크기 변경에도 위치를 갱신한다. `MemoButton`의 `corner`로 선호 모서리를 지정할 수 있다.
- 모바일(화면 너비 700px 이하)에서는 메모 버튼·팝업·카드의 스케줄 수정 바로가기를 렌더링하지 않는다. 워크·태스크 프리셋 상세와 일정 워크·태스크 실행 상세 안에서 메모를 직접 표시·수정한다. 상세 안의 메모 입력은 데스크톱에서도 제공한다.
- 완료 후에도 메모를 수정할 수 있다. 기존 취소된 태스크의 실행 잠금 정책은 유지한다.
- 메모 팝업은 비모달 dialog이며 상위 선택·완료·일정 저장 동작을 실행하지 않는다. 상세 모달 안에서는 해당 모달에 연결한다.
- 메모만을 위한 저장 버튼은 없다. 팝업·상세 공통으로 마지막 입력 600ms 후 자동 저장하고, blur·닫기·화면 이동 시 대기 중인 변경을 즉시 저장한다. 저장 중에도 입력할 수 있으며 요청을 직렬화해 최신 입력을 마지막에 저장한다. 새 일정 조립 중 메모는 조립 초안에 반영하고 일정 생성 시 서버에 저장한다.
- 자동 저장 예정·대기 설명문은 표시하지 않고 실제 저장 중·완료·실패·재시도만 표시한다. 팝업 닫기는 저장 성공 후 완료하며 실패하면 입력을 유지한다. 저장된 대상의 상세를 닫거나 모바일로 전환한 경우 실패·진행 중 초안은 앱 세션 내에서 유지되어 다시 열 때 복원한다. 프리셋 원본·다른 일정은 변경하지 않는다.

## 검증

- API 통합 테스트: 기본값, 한글 변수, 동일 변수 반복, 입력값 재수정, 생성/추가, 완료 후 메모, 원본·다른 일정 격리, DB 재접속 후 유지, 잘못된 입력의 rollback.
- UI 테스트: 입력칸 조립 및 실행 편집, 디바운스·연속 입력·늦은 응답·실패 재시도·상세 재진입 초안 복원, 닫기 시 저장, 조회 실패 시 저장 차단, 상위 form 제출 방지, 모달 안 팝업, 모바일 전환 시 버튼·팝업 제거, 상세 내 메모 수정·삭제, 네 모서리 배치와 화면 경계 제한.
- 분리된 QA DB의 실제 브라우저에서 5 → 10으로 일정 생성 → 12로 수정 → 완료 → 특이사항 메모 → 새로고침 유지 확인. 데스크톱 1280×720과 390×844 레이아웃 점검.
- 실제 브라우저: 버튼 중심·팝업 모서리 좌표 일치, 모서리 기준 확대, 카드 hover 전후 두 버튼의 표시, 자동 저장 상태를 확인. 모바일에서는 바로가기·팝업 미렌더링과 상세 메모 자동 저장을 확인.
