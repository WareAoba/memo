# 앱 전역 UI 종합 점검 — 2026-09-26

## 결론

색상·모서리·아이콘·입력·모달의 기본 언어는 통일되어 있다. 화면들이 서로 다른 제품처럼 보이는 수준은 아니다. 다만 **모바일 정보 순서, 중복 탐색, 주요 동작의 표현, 스크롤과 모션의 연결**은 공통 컴포넌트 사용만으로 정리되지 않았다. 레퍼런스를 전부 준수한다고 보기는 어렵다.

이번 점검에서 재현한 레이아웃 결함 2건은 수정했다. 나머지는 아래 개선 제안이며 아직 구현하지 않았다. 기존 작업 트리의 기능 변경은 이번 점검의 구현 성과에 포함하지 않는다.

## 범위와 방법

- 기준: [디자인 시스템](DESIGN_SYSTEM.md), `frontend/src/design-reference.tsx`, 실제 `/design-reference.html`, [SPEC](../SPEC.md)의 화면·실행 계약.
- 브라우저: 1280×900 데스크톱, 390×844 모바일. 다크·라이트 화면을 확인했다. 모든 화면×테마 조합을 전수 확인한 것은 아니다.
- 실제 화면: 당일 요약, 일간·월간·연간 캘린더, 워크·태스크 프리셋 목록, 일정 작성, 태스크 편집, 설정 일반·화면, 디자인 레퍼런스.
- 코드 검토: 일정·워크·태스크 편집, 실행 태스크 연결, 검색 결과, 메모 저장, 공통 모달·버튼·모션·반응형 스타일, 알림 안내.
- 기존 서버는 현재 프런트의 `/api/auth/me`와 맞지 않아 진입 오류가 났다. 별도 포트의 현재 코드 서버와 임시 SQLite에 점검용 워크·태스크·일정을 생성해 검증했다. 실제 `data/`는 사용하지 않았다.
- 사진 업로드, 실제 Web Push 수신, 실제 터치 기기·가상 키보드, 모든 언어·배율·고밀도 일정 조합은 실행 검증하지 않았다. 해당 범위의 이상 없음을 보증하는 보고서는 아니다.

## 수정 완료

### F1. 월간 캘린더의 불필요한 내부 스크롤

- 위치: [calendar.css](../frontend/src/features/workspace/calendar.css)의 `.calendar-bars`.
- 재현: 390px 월간 화면에서 바깥 본문과 달력 표면에 스크롤이 각각 생겼다. 일정이 없는 주에도 동일했다.
- 원인: 막대 레인을 숨겨도 `repeat(4, 26px)`의 고정 격자 행은 남아 있었다. 124px인 주 영역의 scrollHeight가 167px이었다.
- 변경: 실제 표시되는 막대만 행을 만들도록 `grid-auto-rows: 26px`로 변경했다. 축소 연간 달력의 별도 4px 행은 유지했다.
- 확인: 주 영역은 clientHeight/scrollHeight 모두 124px, 달력 표면도 815px/815px로 일치했다. 긴 월간 화면은 바깥 본문 하나로 스크롤한다.

### F2. 태스크 편집의 보관 버튼이 메모 설명 위에 겹침

- 위치: [preset-modal.css](../frontend/src/styles/preset-modal.css)의 `.preset-modal .modal-body > .actions`.
- 재현: 모바일 태스크 편집을 열면 보관 아이콘이 기본 메모 설명 위에 떠 있었다.
- 원인: 전역 모바일 `.actions { position: sticky; bottom: 0 }`가 보관 영역에도 적용됐다. 이미 별도의 고정 저장 footer가 있어 본문 위에 보조 동작까지 떠 있었다.
- 변경: 모달 본문의 직접 자식 actions만 일반 문서 흐름으로 되돌렸다.
- 확인: 실제 계산 스타일이 `position: static`이며 보관 영역은 본문 하단에 위치한다. 메모 설명 위의 겹침이 사라지고 고정 저장 버튼은 유지됐다.

## 남은 개선 항목 — 우선순위순

### P2-1. 모바일에서 목적지 이동과 하위 메뉴 열기가 동시에 발생

- 근거: [Sidebar.tsx](../frontend/src/features/workspace/Sidebar.tsx)의 캘린더·프리셋 링크는 모바일 클릭 시 `onExpanded(true)`와 `setDrawer`를 실행한다.
- 결과: 캘린더나 프리셋으로 이동할 때 본문에 이미 있는 보기/종류 탭과 같은 선택지가 하단 팝오버에도 자동으로 나온다. 콘텐츠를 가리고 추가 클릭을 유도한다.
- 제안: 하단 탭은 목적지 이동만 담당하고, 일간·월간·연간 / 워크·태스크 선택은 본문에서 한다. 데스크톱 펼친 메뉴의 바로가기는 별도로 판단한다.

### P2-2. 모바일 일정 작성에서 이름보다 시계가 먼저 화면을 차지

- 근거: [ScheduleEditor.tsx](../frontend/src/features/schedules/ScheduleEditor.tsx)는 시간 패널 다음에 워크 패널을 렌더링하고 모바일에서는 한 열로 쌓는다.
- 결과: 390×844에서 시간 제목·시각·시계·설명·여러 날 옵션을 지난 뒤 화면 하단에 워크 이름 입력이 나온다. 가장 먼저 해야 할 이름 입력과 태스크 선택이 늦게 발견된다.
- 제안: 모바일 첫 부분을 워크 이름 → 간결한 시간 요약 → 태스크로 구성하고 시간 원판은 펼쳐 조정한다. 기존 원판 기능은 유지한다.

### P2-3. 주요 저장 동작이 아이콘만으로 표현되고 프리셋에서는 늘어남

- 근거: 일정·워크·태스크 편집이 `IconButton icon="save"`를 사용한다. [base.css](../frontend/src/styles/base.css)의 모바일 `.actions button { flex: 1 }` 때문에 프리셋 저장은 가로로 넓어지지만 내용은 작은 디스크 아이콘 하나다.
- 결과: 스크린 리더 이름은 있으나 터치 화면에서는 텍스트 툴팁을 기대하기 어렵다. 레퍼런스의 텍스트 `저장` 버튼과도 표현이 다르다. 일정 저장은 우측 44px, 프리셋 저장은 넓은 막대로 보인다.
- 제안: 고정 footer에 텍스트 `저장`을 쓰고 폭·정렬을 통일한다. 보관·복원처럼 의미 해석이 필요한 동작에도 텍스트를 제공한다.

### P2-4. 일간 태스크의 상세 진입이 우회됨

- 근거: [SavedScheduleCard.tsx](../frontend/src/features/workspace/SavedScheduleCard.tsx)의 모든 태스크 이름이 동일한 `#/schedules/{일정 ID}`로 연결된다. [Schedules.tsx](../frontend/src/features/schedules/Schedules.tsx)는 전체 일정 편집과 상세 정보를 먼저 보여주고 실행 태스크 버튼을 하단에 둔다.
- 결과: 특정 태스크 입력을 하려면 일정 팝업을 열고 다시 해당 태스크를 찾아야 한다. Today의 `수정`은 바로 그 태스크 팝업을 열어 동작이 다르다.
- 제안: 일간 목록에서도 선택한 실행 태스크를 바로 열고, 전체 일정 수정은 일정 헤더에서 제공한다.

### P2-5. 페이지 이동 시 실제 본문 스크롤이 초기화되지 않음

- 근거: [App.tsx](../frontend/src/App.tsx)의 hashchange는 `window.scrollTo(0, 0)`을 실행하지만 스크롤은 `.app-shell > main`이 소유한다.
- 재현: 모바일 연간 화면을 844px 내린 뒤 Today로 이동하면 로딩 중 높이에 따라 clamp된 main.scrollTop 약 25.6px가 남았다. 항상 같은 오프셋이 남는 것은 아니며 데이터 길이에 따라 달라진다.
- 제안: 경로 변경 시 main 자체를 위로 이동시키거나 경로별 위치 복원 정책을 적용한다. 모달 열기·닫기는 원래 위치를 보존한다.

### P2-6. 알림 도움말의 목적지가 현재 UI와 다름

- 근거: [ko.json](../frontend/src/i18n/locales/ko.json)의 `ReminderSettings.setUpTo365DaysInAdvanceToReceive`는 “상단 알림 설정”이라고 안내한다. 현재 알림 설정은 설정 화면의 알림 탭에 있다. 영어·일본어에도 같은 위치 안내가 남아 있다.
- 제안: 세 언어 모두 `설정 → 알림에서 이 기기 알림을 켜세요`에 해당하는 표현으로 바꾼다. 위치가 불안정한 `상단` 같은 말보다 실제 메뉴 이름을 쓴다.

### P2-7. 모션과 hover 피드백이 일부 경로에만 있음

- 근거: [design-system.css](../frontend/src/design-system.css)는 route-content·열린 모달·메뉴의 진입을 처리한다. [PresetModal.tsx](../frontend/src/features/shared/PresetModal.tsx)는 닫을 때 즉시 unmount된다. 설정 본문과 캘린더 모드 변경은 route-content를 다시 만들지 않으며, 연간 월 선택→월간 확대만 별도 애니메이션이 있다.
- 추가: [search.css](../frontend/src/features/schedules/search.css)의 검색 결과와 calendar.css의 막대는 hover 배경이 기본과 동일하다. 공통 버튼의 전환 대상에도 이 링크들은 포함되지 않는다.
- 제안: 모달 퇴장, 설정·보기 전환에 짧은 opacity 전환을 공유하고 클릭 가능한 링크에 분명한 hover/focus 상태를 준다. 입력 즉시 반응해야 하는 컨트롤에까지 불필요한 이동 효과를 넣지는 않는다. 기존 모션 줄이기·없음 설정을 존중한다.

### P3-1. 모바일 설정 본문 폭과 상시 설명 밀도

- 근거: [settings.css](../frontend/src/features/settings/settings.css)는 390px에서도 88px 왼쪽 탭 열을 유지한다. 입력 영역은 약 220px로 좁아지고 설명이 여러 줄로 나뉜다.
- 제안: 모바일 설정은 상단 탭이나 섹션 선택으로 바꾸어 본문 폭을 확보한다. 반복되는 자동 저장 설명은 짧은 상태 표시로 줄인다. 태스크 매개변수 문법·시계 조작 설명은 도움말로 옮기되 키보드/접근성 설명은 유지한다.
- 문구 정리: `컨텐츠`→`콘텐츠`, 일정/스케줄의 제품 용어 통일. 데이터 영향 범위처럼 사용자 판단에 필요한 안내는 삭제하지 않는다.

### P3-2. 작은 달력 막대와 같은 아이콘의 의미 중복

- 근거: 모바일 막대 제목은 10px이고 행 높이는 26px이다. 한 날짜 너비에 들어가는 짧은 일정명도 쉽게 생략될 수 있다. 프리셋 탐색과 앱 설정은 모두 settings 아이콘을 사용한다.
- 제안: 모바일 월간은 날짜·일정 수를 중심으로 요약하고 일간 진입을 쉽게 한다. 한 날짜에 더 많은 막대를 억지로 채우지 않는다. 프리셋에는 재사용 목록을 뜻하는 별도 아이콘을 사용한다.
- 연간의 숫자 없는 월 실루엣과 흰색 뉴모피즘 막대는 현재 명시된 디자인이므로 자체를 결함으로 분류하지 않았다.

### P3-3. 저장 방식과 중복 정보의 위계

- 근거: 프리셋 편집에서 일반 필드는 명시적 저장, 메모는 자동 저장이다. 일정 상세는 시간 편집·진행률·워크 정보·완료/취소·사진·실행 태스크를 한 팝업 안에 이어 붙인다.
- 제안: 자동 저장 영역과 하단 저장 버튼의 적용 범위를 짧은 상태 표시로 구분한다. 일정 상세는 자주 하는 태스크 실행을 앞에 두고 상세 정보는 접는다. Today 요약과 상세의 중복 완료 기능은 서로 다른 작업 맥락이 있으므로 먼저 정보 밀도와 오조작 가능성을 평가한다.

### P3-4. 모바일 캘린더 탭 여백 조정이 cascade에 막힘

- 근거: calendar.css의 모바일 `.calendar-view-switch button { padding-inline: 12px }`는 features 레이어다. components 레이어의 `.preset-switch.calendar-view-switch button { padding: 8px 20px }`가 우선하여 실제 계산값은 20px였다.
- 결과: 선언만 보면 반응형 조정이 된 것처럼 보이지만 실제 화면에서는 적용되지 않는다. 현 390px에서 탭 자체가 넘치지는 않았다.
- 제안: 공통 컴포넌트 레이어 안에 compact 변형이나 여백 변수를 두어 조정한다. specificity를 높여 레이어 계약을 우회하지 않는다.
