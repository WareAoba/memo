각 단계에서 SPEC 검토 → 변경 범위 설명 → 구현 → format/lint/build/test →
실패 수정 → 가능한 수동 확인 → 결과 기록 순서를 지킨다. 깨진 빌드에서 다음 단계로 넘어가지 않는다.

## 인증을 미룬 동안의 설계

- 고정된 로컬 사용자를 backend/src/local_user.rs 한 곳에서 선택한다.
- user_id/FK와 모든 도메인 쿼리의 소유자 범위를 유지한다.
- 요청 본문·헤더로 다른 사용자를 선택할 수 없다.
- 최초 확인한 기기 시간대를 저장한다. 수동 변경 UI는 설정 단계에서 추가한다.
- 인증 도입 시 사용자 선택 지점을 서버 세션으로 교체하고 로컬 데이터 귀속 정책을 별도로 정한다.
- localhost 개발 범위를 유지하며 공개 배포 전 인증과 운영 요건을 완성한다.
- 클라이언트 암호화·기기 키·복구 키는 도입하지 않는다.

## Phase 4 완료: 워크 기본 태스크 연결

### 구현 범위

- work_task_presets migration과 워크 하위 연결 API 계약 확정.
- 워크 상세에 기본 태스크 조회·선택·추가·제거·순서 변경 UI.
- 연결 소유권, 중복/순서, 보관된 프리셋 처리, 원자적 저장 테스트.
- 일정 생성 시 기본 선택으로 사용할 계약을 준비하되 실제 일정 생성은 Phase 5에서 구현.

### 완료 기준

- 워크별 기본 태스크 목록과 순서를 저장하고 재조회한다.
- 다른 사용자 소유 태스크를 연결할 수 없고 같은 태스크의 중복 연결을 막는다.
- 보관된 태스크의 기존 연결 표시와 신규 연결 제한을 명세로 확정한다.
- 기존 워크/태스크 CRUD를 보존하고 format/lint/build/관련 테스트를 통과한다.

위 기준을 충족했다. 보관된 태스크는 기존 연결 유지·재정렬·제거만 허용하며 신규 연결은 거부한다.
검색 재시도는 저장 전 연결 편집을 보존한다. 브라우저 저장·새로고침 검증은 VERIFICATION_PHASE4.md에 기록했다.

## 유지하는 아키텍처 결정

- Rust/Axum/SQLx/SQLite modular monolith와 독립적인 JSON REST 계약.
- 시작 전 migration, foreign keys, WAL, busy timeout.
- 프리셋/대상 변경은 기존 실행 snapshot에 영향을 주지 않는다.
- Vite/Caddy의 동일 origin /api 경로 유지.
- 의존성과 추상화는 실제 기능을 구현할 때 필요한 만큼 추가한다.
- 자동 commit, 원격 저장소 생성, 공개 배포는 현재 범위가 아니다.
