# 화면 골격·용어 정리 검증

검증일: 2026-09-24 · SPEC.md v1.3

## 확정 구조

- 워크 = 현장·과목·고객·프로젝트 같은 재사용 대상(Entity).
- 태스크 = 워크에 붙여 수행할 일. 프리셋 정의와 일정의 실행 상태를 구별한다.
- 일정 = 워크를 특정 날짜·시간에 배치한 한 번의 실행.
- 주 탐색 3개: 당일 요약 / 전체 캘린더 / 프리셋 설정.
- 프리셋 하위 탐색 2개: 워크 / 태스크.
- 워크 블록 상단에 이름·시작/종료 시간, 안쪽에 개별 태스크 블록과 완료 체크.
- Phase 4 계획은 별도 PresetSet 화면 대신 워크의 기본 태스크 연결로 조정.

## 반영 사항

- 기본 시작 화면을 당일 요약으로 변경. 데스크톱 상단/모바일 하단 탐색.
- 워크 기본 입력을 이름·설명/메모·태그로 단순화.
- 참조 코드·장소·연락처·이용 가능 시간·방문 정보는 접힌 선택 정보로 이동.
- 목록의 관리번호/주소 미등록 문구를 없애고 설명·태그 중심으로 표시.
- 기존 DB와 /api/entities 계약 유지. 기존 #/entities 링크도 호환.
- 당일 요약과 월 캘린더는 WorkBlock을 공유하고 예시 체크 상태도 공유.
- 날짜가 다른 같은 워크의 태스크는 독립 상태.
- 태스크 프리셋 탭은 분류별 구성 예시를 제공.
- 예시 데이터는 브라우저 메모리에만 존재하고 서버에 저장하지 않는다.

## 자동 검증

`npm run check:frontend` 통과:

- Prettier / ESLint / TypeScript / Vite production build.
- Vitest 4개 파일, 26개 테스트.
- 기존 워크 CRUD 화면과 API 오류 처리 회귀.
- 편집 후 기존 주차·계약 메모 및 다른 선택 정보가 요청에 유지됨을 확인.
- 주 메뉴 3개, 프리셋 하위 메뉴 2개, 기본 시작 화면.
- 당일 요약/캘린더 사이 체크 상태 공유, 완료 취소, API mutation을 호출하지 않는 예시 동작.
- 예시 표시 끄기/켜기, 태스크 분류, 캘린더 월 이동/오늘 복귀.
- 윤년·일요일 시작 월·연도 경계·로컬 날짜 키 검증.

최종 build: JS 248.72 kB (gzip 77.49 kB), CSS 14.70 kB (gzip 3.78 kB).
백엔드 코드·migration·의존성 변경이 없어 이번 작업에서 backend 전체 테스트는 재실행하지 않았다.
Phase 2 당시 backend 검증은 VERIFICATION_PHASE2.md에 보존한다.

## 브라우저 확인

- 390×844 viewport: 당일 요약/캘린더/워크 등록 화면과 고정 하단 탐색 확인.
- 가로 넘침 없음. 캘린더 날짜 버튼은 이 크기에서 폭 약 44.5px, 높이 66px.
- 태스크 체크 후 워크 진행률 1/3 → 2/3, 당일 진행률 1/8 → 2/8 확인.
- 캘린더에서도 변경된 체크 표시. 다음 날짜의 영어 워크는 0/2로 독립 상태 확인.
- 워크 등록의 기본 입력 3종과 선택 정보 펼치기 확인.
- 기존 워크 API 목록 응답과 프런트 연결 확인.
- 중단되어 있던 Vite 개발 서버를 재실행하고 API 연결 복구 확인.

## 범위와 다음 단계

실제 저장 기능은 워크 CRUD까지다. 일정·태스크 프리셋·실행 저장 API는 아직 없다.
예시 데이터/완료 체크는 레이아웃 검토용이며 새로고침하면 초기화된다.
완료 체크에 대한 필수 세부 항목 검증, 완료 취소 저장, snapshot은 후속 단계에서 연결한다.
브라우저 viewport 검증이며 실제 모바일 기기 테스트는 아니다. Docker/원격 CI는 이번에 실행하지 않았다.
다음 기능 단계는 Phase 3 태스크 프리셋, 그다음 Phase 4 워크 기본 태스크 연결이다.
